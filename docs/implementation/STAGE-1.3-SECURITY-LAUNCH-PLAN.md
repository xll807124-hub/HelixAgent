## 📐 每个需求的详细计划

### REQ-SEC-004：沙箱隔离（4 天）

**目标**：实现 Docker 容器隔离，支持代码执行和工具调用

**关键组件**：
```
security/sandbox/
├── docker_backend.py      # Docker API 客户端
├── container_manager.py   # 容器生命周期管理
├── network_config.py      # 网络隔离配置
├── resource_limits.py     # CPU/内存/磁盘限制
└── escape_prevention.py   # 逃逸检测（可选，MVP 后）
```

**验收标准**：
- [ ] 能启动受限容器
- [ ] 网络默认拒绝，白名单通过
- [ ] CPU ≤ 2核、内存 ≤ 4GB、磁盘 ≤ 10GB
- [ ] 超时保护（15 分钟强制终止）
- [ ] 100% 逃逸测试失败（无法逃逸）

**依赖**：Docker Engine（需环境支持）

---

### REQ-SEC-005：凭据代理（2 天）

**目标**：GitHub App 集成，签发短期凭据，消除长期凭据存储

**关键组件**：
```
security/credential/
├── github_app.py          # GitHub App 整合
├── token_manager.py       # 短期凭据生成
├── rotation_policy.py     # 凭据轮换策略
└── audit_logging.py       # 凭据使用审计
```

**验收标准**：
- [ ] GitHub App 认证成功
- [ ] 签发的凭据有效期 ≤ 1 小时
- [ ] Agent 不存储长期凭据
- [ ] 凭据使用完全审计

**依赖**：GitHub App 配置（需团队提供）

---

### REQ-SEC-006：Prompt 注入防护（2 天）

**目标**：检测并阻止 Prompt 注入攻击

**关键组件**：
```
security/prompt_injection/
├── detector.py            # 注入检测引擎
├── patterns.py            # 攻击模式库
├── risk_scorer.py         # 风险评分
└── blocklist.py           # 关键字/模式黑名单
```

**检测策略**：
1. **模式匹配**：已知 Prompt 注入模式
2. **熵分析**：异常低/高熵输入
3. **语义分析**：系统角色冲突指示符
4. **统计异常**：输入长度、字符分布异常

**验收标准**：
- [ ] 检测率 > 95%
- [ ] 假正率 < 5%
- [ ] 检测延迟 < 100ms
- [ ] 对抗样本测试通过

---

### REQ-SEC-007：MCP 连接器治理（1 天）

**目标**：建立连接器注册表和信任管理

```
security/mcp_governance/

├── trust_levels.py        # 信任等级管理
├── approval_workflow.py   # 审批流程
└── connector_validator.py # 连接器验证
```

**验收标准**：
- [ ] 连接器可注册和验证
- [ ] 信任等级准确分配
- [ ] 审批流程可追踪

---

### REQ-SEC-008：多租户隔离（1 天）

**目标**：实现租户数据完全隔离

**关键实现**：
1. **查询层**：所有查询强制添加 `tenant_id` 过滤
2. **索引层**：按租户分区
3. **缓存层**：租户隔离 Key
4. **审计层**：跨租户访问尝试记录

**验收标准**：
- [ ] 跨租户数据泄露测试 100% 失败
- [ ] 所有查询都包含租户校验
- [ ] 性能无显著下降

---

### REQ-SEC-009：Kill Switch 机制（1 天）

**目标**：紧急止血开关，支持多层粒度

**关键组件**：
```
security/kill_switch/
├── state_machine.py       # M0-M5 六模式
├── policy_router.py       # 分层路由（ACTION/TOOL/TASK/PROJECT/ORG/GLOBAL）
├── break_glass.py         # Break-Glass 授权
└── effectiveness_monitor.py # 生效验证
```

**验收标准**：
- [ ] Kill Switch 在 10 秒内生效
- [ ] 支持 6 种模式（M0-M5）
- [ ] 支持 6 层粒度
- [ ] Break-Glass 完整审计
