## 1. 需求定义

### 1.1 目标

为 AI Agent 平台定义统一的用户、服务身份、组织、项目、仓库、路径和操作授权模型。平台必须在上下文读取、检索结果返回、工具调用、凭据签发和审计查询之前完成授权；Agent、模型、Worker 声明和外部内容都不是授权主体或授权依据。

该设计提供确定、可解释、默认拒绝的授权结果，供 Policy Gateway 组合风险策略、审批状态和执行限制。授权范围不得超出发起用户在关联代码托管平台上的有效权限，也不得超出组织策略授予平台的能力。

### 1.2 问题与用户价值

原待办仅提出“用户、组织、项目、仓库、路径授权模型”，没有定义身份来源、角色能力、层级继承、拒绝优先级、路径语义、权限撤销时效、缓存一致性、降级行为和审计要求。若这些规则留给各消费者自行解释，将造成跨租户读取、管理员隐式越权、缓存陈旧、检索泄露以及 Agent 工具调用绕过等风险。

设计目标是让组织管理员能管理成员与资源授权，让任务发起者能在自身权限内启动 Agent，让 Policy、Context、Credential 和 MCP 消费者引用相同的授权语义，让安全审计员能还原“谁基于何种策略对哪个资源、哪个操作作出何种决定”。

### 1.3 范围

包含：身份及主体类型、角色与权限、组织/项目/仓库/路径/操作资源层级、继承与拒绝规则、代码托管平台权限上限、授权评估、权限变更审批、紧急临时授权、缓存失效、失效关闭、审计、验收和版本演进。

不包含：完整策略语言、风险评分矩阵、通用审批工作流协议、凭据铸造与撤销、MCP 连接器生命周期、多租户存储隔离实现、上下文索引算法。这些分别由 `REQ-SEC-001`、`REQ-SEC-003`、`REQ-SEC-005`、`REQ-SEC-007`、`REQ-SEC-008` 和 `REQ-CTX-005` 定义。

### 1.4 设计不变量

1. 未明确允许即拒绝；拒绝规则优先于允许规则。
2. 租户、组织和资源归属校验必须先于资源查询或内容加载。
3. 用户、Agent/Worker、服务身份分别识别；Agent 权限不得超过发起用户权限、组织策略上限及已批准任务范围三者的交集。
4. RBAC 决定主体可申请的操作范围；资源属性、路径、数据敏感度、任务范围和风险等条件可进一步收紧，不能扩大 RBAC 上限。
5. 组织管理员身份不自动授予敏感仓库内容读取权；访问须有显式资源授权。管理操作权限和内容访问权限分离。
6. Worker 的 `allowed_tools`、`allowed_resources` 和模型建议只是候选能力，不构成授权。
7. 权限服务不可用、身份不完整、租户不匹配、策略版本未知或授权上下文无法验证时，一律拒绝受保护操作。
8. 权限决策和权限变更必须可审计；审计记录不得包含凭据或不必要的源码内容。

## 2. 共享概念与权限模型

### 2.1 主体

- **用户主体**：经身份适配层验证的自然人账号，带稳定平台主体 ID、身份提供方命名空间和组织成员关系。
- **团队主体**：组织内的团队或组，用于角色分配；其成员关系来自本平台权威目录或经验证的 IdP 同步结果。
- **服务主体**：受控的平台服务身份，仅限明确的服务间职责，不等同于用户。
- **Agent/Worker 主体**：运行时派生身份，必须关联发起用户、Task、Workflow、Worker 和 Trace；不独立登录、不持久持有长期凭据。

每项授权评估至少具有可验证的主体、组织、目标资源、操作、任务上下文和当前策略版本。缺失必要属性时不得用模型推断补全。

### 2.2 资源层级与操作

资源层级为：平台（仅平台治理）→ 组织 → 项目 → 仓库 → 仓库内路径；操作作为资源动作维度单独判定。MVP 用户内容访问不支持跨组织继承。项目和仓库必须具有唯一组织归属，关系不一致即拒绝。

初始操作类别：查看/读取、搜索/检索、创建任务、修改任务工作区、执行测试或命令、创建分支/提交、创建 PR、管理成员/角色/策略、查看审计。具体工具动作到操作类别的映射由 `REQ-SEC-003` 和 `REQ-HAR-003` 细化；未知或未映射的动作拒绝。

敏感仓库、受限路径及高风险操作可以通过资源属性或显式拒绝进一步收紧权限。组织管理员的成员、角色和策略管理能力不自动包含仓库内容读取、检索、导出或 Agent 执行权限。

### 2.3 角色基线

MVP 定义平台治理管理员、组织管理员、项目管理员、开发者/任务发起者、安全审计员等角色模板。角色模板是可配置的权限集合，不是硬编码的隐式超级权限。组织管理员只能在所属组织内管理组织成员和授权配置；读取敏感仓库需要另外授予相应的仓库及操作权限。安全审计员默认只读审计信息，不因此获得源码访问权。

角色可分配给用户或团队，授权绑定组织范围，资源级授权可在所属资源范围内缩小或授予明确操作。禁止通过角色重叠产生隐式全局管理员能力。平台级管理权限仅作用于平台治理资源，不等价于租户内容访问。

### 2.4 继承、冲突与上限

授权评估按以下约束综合：主体有效角色权限、资源链上的允许规则、显式拒绝规则、任务授权范围、组织策略上限、代码托管平台权限上限和当前审批/风险约束。结果必须满足所有硬约束；任一硬约束拒绝或未知，最终拒绝。

父级允许可以向下继承，但不能绕过子级显式拒绝、敏感资源的显式授权要求或外部平台权限上限。子级授权只能在父级授权可委派范围内生效，不能授予授权者自身不具备或无权委派的能力。MVP 不提供任意权限委托链。

对仓库及代码内容的可用权限上限为：发起用户有效权限、组织连接授权范围、平台任务批准范围三者交集。即使平台连接凭据权限较宽，也不得因此提升用户权限。

### 2.5 路径匹配

MVP 只支持规范化后的精确路径匹配和目录前缀匹配，不支持 glob、正则、否定通配表达式或依赖主机文件系统语义的模式。路径按仓库相对路径解释；统一分隔符、拒绝绝对路径和父目录穿越，处理大小写时遵循仓库平台语义并以仓库配置为准。无法规范化、存在编码歧义或匹配规则冲突时拒绝。

路径规则遵循最具体规则优先；同一具体度下显式拒绝优先。仓库级访问允许不自动覆盖敏感路径的显式拒绝。路径策略须在读取、搜索、索引返回、工具响应和写入各入口执行，不能只在 UI 隐藏。

## 3. 身份集成与生命周期

平台通过抽象身份提供方适配层接入多种 IdP，不将某个供应商的角色声明、组名或主体 ID 直接当作跨系统稳定契约。适配层负责认证结果验证、主体标识命名空间、组织映射、组/角色声明映射、成员停用状态及必要的凭证更新语义。

身份认证与平台授权分离：IdP 证明身份和提供经验证的目录属性；本平台的授权服务将这些属性映射到平台角色与资源授权。来自外部 IdP 的组或角色不能自动成为平台管理员角色，必须由组织管理员显式映射并经过变更审批。身份映射不完整、声明过期或签名验证失败时，受保护操作拒绝。

MVP 支持通过适配层接入首个身份提供方，并保持后续可替换；具体首发 IdP、同步频率、SCIM 支持和组织成员生命周期尚未由本需求确认，属于实施前置决策。代码托管平台授权与企业 IdP 身份是两个独立信任来源，二者均需校验。

## 4. 授权评估流程

### 4.1 请求上下文

授权请求概念上包含：主体及其身份来源、组织/项目/仓库/路径资源引用、操作类别、Task/Workflow/Worker/Action 引用、资源敏感级别、当前策略版本、审批凭据引用（如适用）和 Trace 关联。不得把令牌秘密、完整源码或模型思维链放入请求审计载荷。

### 4.2 决策步骤

1. **验证身份**：验证认证状态、主体类型、身份提供方和成员状态；Agent 主体必须回溯到发起用户及运行实体。
2. **验证租户与归属**：确认主体属于目标组织，项目/仓库/路径关系一致；跨租户或缺少归属即拒绝。
3. **规范化资源和操作**：验证资源引用、仓库相对路径、操作映射和任务资源边界；未知操作拒绝。
4. **求取角色能力**：读取主体及团队角色，在组织边界内合并其明确授予的能力；不推断管理员的内容访问权。
5. **应用资源规则**：从组织、项目、仓库到路径应用继承约束和显式拒绝；校验敏感资源是否存在明确授权。
6. **应用权限上限**：与组织策略、用户在代码托管平台的权限、任务批准范围及 Worker 能力声明取交集。
7. **应用条件与审批状态**：将数据敏感度、风险级别、时间有效性和 `REQ-SEC-003` 的审批结果作为进一步约束。RBAC 服务不自行批准风险例外。
8. **形成决策**：返回允许或拒绝、规范化资源、操作、适用授权来源、拒绝/限制原因、策略版本和有效期。任何未决条件按拒绝处理，等待 Policy Gateway 决定是否进入审批流程。
9. **执行前复核**：在实际资源访问或副作用发生前再校验授权有效性，避免上下文加载后的权限撤销竞态；写操作、高风险操作不得仅依赖任务开始时的旧决定。
10. **审计与传播**：记录决策事件并传播最小化的授权上下文，供 Policy Gateway、Context、Credential、MCP 和审计消费者使用。

权限检查必须早于内容访问。对于检索，先按组织、仓库和路径做授权约束，再向模型或调用者返回候选结果，禁止“先检索后在 UI 过滤”。

### 4.3 决策可解释性

拒绝结果至少区分身份无效、组织不匹配、资源不存在/归属异常、无角色能力、显式拒绝、敏感资源缺少显式授权、外部平台权限不足、审批缺失/过期、策略未知和服务不可用。面向终端用户只披露必要原因，防止通过错误差异探测其他租户资源；审计视图可记录更完整的内部原因。

## 5. 权限变更与审批

### 5.1 变更流程

权限创建、扩大、缩小、撤销、角色映射和 IdP 组映射均视为授权变更。系统验证请求者的管理权限及其可委派范围，检查目标主体和资源归属，计算影响范围，确定风险等级与所需审批层级，再执行原子变更。变更成功后产生不可变审计事件、递增授权版本、触发缓存失效并通知相关管理者。失败时不得呈现为部分成功；若权威数据已提交但通知/失效未完成，变更保持已提交状态并由可靠事件传播重试，期间执行授权必须采用保守语义。

### 5.2 按权限级别设置多级审批

权限变更审批级别由操作敏感度、影响资源范围、被授予权限、目标数据级别和请求者职责确定。低影响的范围内成员变更可由有权组织管理者批准；扩大仓库内容访问或写能力需要资源所有者/项目负责人按组织策略批准；涉及敏感仓库、管理员角色、跨团队映射或高风险能力时，必须由不同职责的第二审批人（例如安全职能）人工批准。请求者不得批准自己的提权请求；审批人不得仅凭模型生成的风险判断放行。

具体角色组合、审批超时和策略版本绑定由 `REQ-SEC-003` 的统一审批矩阵确定。本需求规定：未完成要求的审批不得生效；审批绑定主体、资源、操作、范围、理由、过期时间及授权策略版本；任一关键事实变化、请求范围扩大或策略版本改变，须重新审批。

### 5.3 紧急临时授权

紧急授权按被授予权限级别区分：低风险且范围受限的权限可按组织预先批准的流程授予短时能力并触发即时通知；中风险授权须至少一名具备相应职责的审批人确认；高风险、敏感仓库内容访问、管理员角色、广泛写入或跨组织能力必须人工审批，禁止自动批准。紧急理由、关联事故/任务、目标资源和所需操作必须明确。

临时授权是短期、不可扩展的显式授权，不得通过继承变成更大范围；到期或事故关闭时自动失效，可提前撤销。访问使用全程审计。MVP 不设绕过审批的 break-glass 超级通道；若业务需要该机制，须单独进行威胁评估并由 `REQ-SEC-003/009` 定义。

## 6. 缓存、一致性与故障处理

### 6.1 缓存策略

采用服务本地缓存常用角色、资源关系和授权决策，并通过分布式失效事件通知所有实例清除受影响条目。缓存键必须包含主体、组织、资源、操作和策略/授权版本，避免跨主体或跨租户复用。缓存不得成为授权事实源；权威授权数据和版本由授权服务持有。

每次授权变更都递增相关授权版本并发布失效事件。实例收到事件后清除对应主体、资源和继承链条目；不能确认失效已应用时，不允许继续使用可能陈旧的放行决定。执行前的高风险和写操作决策需校验当前授权版本。缓存条目另设有限有效期作为失效消息丢失的上限，但具体 TTL 需由实现基准和安全评审确定，本设计不承诺未经测量的固定值。

### 6.2 故障策略

授权服务、权威数据源、失效通道或身份校验任一关键依赖不可用时，对所有受保护的资源读取、检索、写入、执行、凭据签发和权限管理操作 fail-secure：拒绝或暂停，不使用陈旧缓存放行。可继续不触及受保护资源的纯本地状态查看、错误提示和审计恢复工作。失败须返回可重试的系统不可用类别，不伪装成用户无权限；拒绝访问不得自动重试成授权成功。

## 7. 数据流、状态与审计

权威授权配置由授权服务管理，身份属性来自已验证的适配层，外部代码托管平台权限作为上限输入。授权评估从运行时的 `organization_id`、`project_id`、`repository_id`、`task_id`、`worker_id`、`allowed_resources`、Action `target_resources`、操作类型及 Trace 坐标构建。决策结果传给 Policy Gateway；仅经过其统一风险/审批决策后才能执行。

授权变更和评估均产生审计事实，关联操作者、受影响主体、资源、操作、决定、理由类别、变更前后授权版本、审批引用、时间和 Trace。审计应遵循 `REQ-RT-003` 事件事实源、`REQ-RT-006` Trace 传播和 `REQ-RT-008` 查询、脱敏、留存与访问权限约束。不得记录秘密凭据或不必要的代码内容。普通运行遥测可采样；安全授权决策审计不得因 Trace 采样而丢失。

授权缓存和查询投影可重建；审计事实不可由缓存状态替代。授权撤销后，当前任务的下一次受保护操作必须重新评估；已签发的外部凭据撤销语义由 `REQ-SEC-005` 明确定义，不能假设 RBAC 缓存失效会自动撤销下游凭据。

## 8. 安全、隐私与合规约束

- 所有授权均绑定组织租户范围；资源查询和数据库访问须防止缺失租户过滤。
- 对象级授权不仅检查资源 ID，也检查其组织归属，防止 IDOR 与跨租户混淆。
- Agent 输出、仓库文件、Issue、工具返回和检索文本均为不可信数据，不能修改授权规则。
- 敏感仓库内容访问、数据导出、管理角色授予和高风险写权限须显式授权及人工审批（适用时）。
- 组织管理员不能通过管理界面、审计入口、检索服务或后台工具隐式读取无权访问的代码。
- 授权决策日志遵循数据最小化、访问控制、脱敏和留存规则；审计员只可访问其职责范围所需的元数据。
- 授权策略和 IdP 映射必须版本化、可回滚；回滚不得抹除变更审计事实。
- 本设计不构成任何认证或法规合规声明；合规控制映射由安全治理和审计工作补足。

## 9. 性能、成本与可观测性

授权发生在敏感操作路径上，性能优化不得降低撤销及时性或租户隔离。优先通过本地缓存、按授权版本复用、批量预取和请求内去重降低重复查询；预取只能减少延迟，不能在执行前替代当前版本校验。审批和审计写入不能阻塞低风险决策的方式须由 `REQ-SEC-003` 与事件系统评审，但安全关键审计失败时不得静默放行。

观测指标至少包括授权决策延迟分布、允许/拒绝/服务故障数量、按拒绝原因分类的比率、缓存命中和失效传播延迟、版本不一致次数、敏感资源未授权尝试、审批等待/超时、紧急授权数量和过期回收延迟。指标标签不得包含高基数用户 ID、路径全文或源码；安全调查所需细节写入受控审计事件。

性能目标应在代表性主体/角色/资源规模和并发模型下基准测试后确定。当前不将先前草案中未经验证的固定延迟、缓存命中率或 QPS 数值作为验收门槛。

## 10. 异常场景

| 场景 | 行为 |
|---|---|
| 身份失效、签名无效或成员已停用 | 拒绝受保护操作，记录身份校验失败类别 |
| 组织/项目/仓库归属不一致 | 拒绝并记录完整性安全事件，不查询资源内容 |
| 资源或操作类型未知 | 默认拒绝，要求消费者完成显式映射 |
| 授权规则冲突 | 显式拒绝优先；同级冲突拒绝并告警 |
| 敏感仓库缺少直接访问授权 | 拒绝，即使请求者是组织管理员 |
| 路径含越界、歧义或规范化失败 | 拒绝，不回退为仓库根访问 |
| 授权撤销与任务执行并发 | 执行前重新校验版本；无法确认时暂停/拒绝 |
| 缓存失效事件丢失或延迟 | 版本校验失败时拒绝；不得陈旧放行 |
| IdP 不可用或属性不完整 | 拒绝需依赖实时属性的操作，不扩大已知权限 |
| 审批过期或授权事实变化 | 视为无有效审批，重新申请 |
| 授权服务/存储不可用 | Fail-secure 拒绝所有受保护操作 |
| 审计事件提交失败 | 安全敏感授权变更不得报告完成；执行类操作按安全策略暂停/拒绝 |

## 11. 依赖与接口边界

### 11.1 上游

- `REQ-RT-001`：使用 `organization_id`、`project_id`、`repository_id`、`ActorRef`、`ResourceRef`、Task/Workflow/Worker/Action 标识、Worker `allowed_resources`、Action `target_resources` 和 Trace。
- 身份适配层：提供已验证主体和组织/组属性；本需求不选择特定 IdP。
- 代码托管平台连接：提供用户和安装授权的有效范围，作为平台权限上限；具体同步/令牌协议不在本需求范围。
- `REQ-SEC-001`：提供数据分级和风险分类基础。

### 11.2 下游

- `REQ-SEC-003` Policy Gateway：消费授权判定、理由、版本和审批约束，统一产生 Action 的执行决策。授权服务不直接调用工具，也不绕过 Policy Gateway。
- `REQ-SEC-005` 凭据代理：仅在授权允许且策略审批有效时签发严格限于资源/操作/期限的短期凭据，并定义撤销传播。
- `REQ-SEC-007` MCP 治理：对连接器主体及其每项工具调用应用同一主体、资源和操作授权语义。
- `REQ-SEC-008` 多租户数据治理：以组织范围、租户隔离和审计控制为数据平面约束。
- `REQ-CTX-005` 检索权限：在查询执行和候选内容返回前应用仓库/路径权限过滤，不得事后过滤。
- `REQ-RT-008` 审计查询：按授权角色控制对授权事件的查询，并执行脱敏和留存策略。

概念接口只交换主体、资源、操作、运行上下文、授权版本、判定及原因类别；不在本需求冻结具体网络协议、数据库 DDL、策略语言或令牌格式。

## 12. 验收标准

| 编号 | 可验证标准 | 验证方式 |
|---|---|---|
| SEC-002-AC1 | 未认证、已停用或不属于目标组织的主体不能读取、检索或修改该组织资源 | 身份与授权集成测试 |
| SEC-002-AC2 | 对象 ID 指向其他组织资源时，在读取资源内容前拒绝 | 跨租户/IDOR 安全测试 |
| SEC-002-AC3 | 组织管理员未获敏感仓库显式授权时不能读取、检索、导出或委派 Agent 访问该仓库 | 角色边界测试 |
| SEC-002-AC4 | Agent 可用权限不超过用户权限、组织策略、代码托管平台授权和任务批准范围的交集 | 权限上限属性测试 |
| SEC-002-AC5 | 显式拒绝优先于继承允许；未定义操作、未匹配资源及不确定条件默认拒绝 | 冲突与负向测试 |
| SEC-002-AC6 | 路径精确匹配和前缀匹配按仓库相对路径确定工作；MVP 不接受 glob/正则；路径穿越和规范化歧义被拒绝 | 路径边界测试 |
| SEC-002-AC7 | 权限判断发生在内容读取、检索结果返回、工具执行和凭据请求之前 | 调用顺序与数据泄漏测试 |
| SEC-002-AC8 | 权限变更由具备委派范围的主体发起，按风险级别满足审批；请求者不能批准自身提权 | 审批矩阵测试 |
| SEC-002-AC9 | 高风险临时授权必须有人工审批，范围有限且按级别配置有效期；到期后下一次操作被拒绝 | 时间控制与流程测试 |
| SEC-002-AC10 | 权限变更原子生效，生成含前后版本、主体、资源、操作、审批引用和 Trace 的审计事件 | 事务与审计测试 |
| SEC-002-AC11 | 本地缓存收到分布式失效后不再返回旧授权；无法确认当前版本或授权依赖不可用时受保护操作一律拒绝 | 多实例并发/故障注入测试 |
| SEC-002-AC12 | 任一允许决定可解释其授权来源和版本；任一拒绝可归类且不泄露其他租户资源存在性 | 决策解释与隐私测试 |
| SEC-002-AC13 | 任意 Agent Action 越权、跨组织、使用过期审批或策略版本均被 Policy Gateway 拒绝并审计 | 端到端安全测试 |
| SEC-002-AC14 | 服务恢复后，失败期间拒绝的操作不会自动转为已授权副作用；用户须重新发起或按可靠性策略处理 | 故障恢复测试 |

详细性能目标在实现基准和安全评审后建立；本需求的设计验收不以未经测量的吞吐数字代替安全正确性。

## 13. 版本范围与演进

### MVP

- 用户、团队、服务及派生 Agent 主体；组织、项目、仓库、路径和操作授权。
- 基础 RBAC 角色模板，显式资源授权及拒绝优先。
- 与外部 IdP 解耦的适配层；首个 IdP 由部署决策确定。
- 路径精确匹配和前缀匹配，不含 glob/正则。
- 本地缓存与分布式失效；不确定状态 fail-secure。
- 按权限风险等级审批；高风险紧急授权必须人工审批并设差异化到期时间。
- 授权版本、审计事件、执行前重新校验。

### 后续版本候选

完整条件策略、SCIM 自动化、细粒度职责分离矩阵、自助权限申请、权限影响图、只读权限快照、额外路径匹配表达式等均为候选扩展，需经安全评估、兼容性分析和实测决定。本设计不预先承诺自动提权或完整 glob。

### 冻结条件

本设计标记为 `v0.1-designed`，须经安全、运行时、Policy、Context、Credential、MCP 和多租户相关方交叉评审，并完成授权矩阵、缓存失效一致性、敏感仓库访问和故障注入方案确认后，才可升级为冻结版本。设计完成不代表实现或安全验证完成。

## 15. 关键设计决策记录

| 决策 | 选定基线 | 理由/边界 |
|---|---|---|
| 权限缓存 | 服务本地缓存 + 分布式失效 | 降低评估路径开销，同时通过授权版本和失效传播控制撤销；依赖不确定即拒绝 |
| 路径模式 | MVP 精确匹配 + 前缀匹配 | 降低模式歧义与实现攻击面；暂不支持 glob/正则 |
| 紧急授权 | 按权限级别区分，高风险必须人工审批 | 限制自动提权风险；审批人不能是请求者 |
| 组织管理员 | 访问敏感仓库须显式授权 | 管理职责与内容访问分离 |
| 权限变更审批 | 按权限级别设置多级审批 | 高影响变更引入职责分离；具体矩阵由 SEC-003 补充 |
| 外部 IdP | 抽象适配层，支持多种 IdP | 将身份认证与本平台授权解耦；首发提供方待部署决策 |
| 故障降级 | 授权服务不可用时拒绝所有受保护访问 | 避免陈旧授权造成越权 |
| 临时授权时限 | 按权限级别设置不同到期时间 | 有效期与风险相称；具体时限由 SEC-003 审批矩阵给出 |
| RBAC/ABAC 边界 | RBAC 定上限，属性/风险/审批只可收紧 | 防止条件规则隐式扩大角色能力 |
| 冻结状态 | `v0.1-designed`，待交叉评审 | 设计完成不等于冻结、实现或已验证 |
