## 三、推荐执行顺序

### 阶段 0：设计冻结（4-6 周）

**目标**：统一所有模块的共享锚点

**并行工作流**：

#### 流 1：核心契约（2-3 周）
```text
Week 1-2: 
  - 定义核心实体 Schema（Task, Action, Artifact, Evidence）
  - 设计状态机和迁移规则
  - ✅ 完成事件模型和版本策略详细设计（`REQ-RT-003`）
  - ✅ 完成状态投影与一致性规则详细设计（`REQ-RT-004`）
  - 实现事件写入和投影 PoC

Week 3:
  - ✅ 完成 REQ-RT-005 检查点格式、保存与恢复协议详细设计
  - 验证恢复性能
  - 架构评审并冻结 v1
```

**责任人**：架构师 + 后端 Lead  
**验收标准**：Schema 文档、状态机图、事件 Schema、PoC 代码

#### 流 2：威胁模型（2-3 周）
```text
Week 1:
  - 完整威胁清单和攻击树
  - 风险评分矩阵
  - MVP 覆盖范围确定

Week 2:
  - 沙箱技术选型和基准测试
  - 凭据代理设计
  - 控制措施分配

Week 3:
  - Kill Switch 设计
  - 事故响应流程
  - 安全评审
```

**责任人**：安全架构师 + DevSecOps  
**验收标准**：威胁模型文档、控制矩阵、沙箱选型报告、凭据方案

#### 流 3：失败分类（1-2 周）
```text
Week 1:
  - 定义失败类型枚举
  - 设计 RetryPolicy Schema
  - 编写决策规则

Week 2:
  - 设计幂等键生成规则
  - 定义补偿工作流
  - 文档评审
```

**责任人**：可靠性工程师  
**验收标准**：失败分类文档、RetryPolicy Schema、幂等性设计

#### 流 4：评估准备（2-3 周）
```text
Week 1-2:
  - 收集和脱敏历史任务（目标 50 个）
  - 构建安全对抗样本（目标 30 个）
  - 定义标注规范

Week 3:
  - 招募标注人员
  - 开始人工标注
  - 设计评分器接口
```

**责任人**：QA Lead + ML Engineer  
**验收标准**：Golden Dataset v0.1、标注规范、评分器接口设计

**阶段门禁**：
- [ ] 所有 Schema 已冻结并通过评审
- [ ] 状态机和事件模型已验证
- [ ] 威胁模型和控制矩阵已完成
- [ ] 失败分类和重试策略已定义
- [ ] Golden Dataset v0.1 包含至少 50 个任务

## 五、风险与应对

### 技术风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| 事件存储性能不足 | 高 | 中 | 提前进行压力测试，准备分片方案 |
| 检查点恢复时间过长 | 中 | 中 | 优化检查点大小，使用增量检查点 |
| 沙箱冷启动慢 | 中 | 高 | 使用 WarmPool，选择 Firecracker |
| 检索质量不达标 | 高 | 中 | 准备多种检索方案对比，及时调整 |
| 模型成本超预算 | 高 | 中 | 设置严格预算限制，优化 Prompt |

### 组织风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| 人力不足 | 高 | 中 | 优先完成 P0 功能，适当削减范围 |
| 跨团队协作困难 | 中 | 高 | 定期同步会，明确责任边界 |
| 需求变更频繁 | 中 | 高 | 先冻结核心契约，减少返工 |
| 安全审计延期 | 高 | 中 | 提前启动安全评审，并行推进 |

### 外部风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| 模型 API 限流 | 高 | 中 | 准备多个供应商，支持降级 |
| 开源工具停止维护 | 中 | 低 | 选择成熟度高的工具，准备 Plan B |
| 合规政策变化 | 高 | 低 | 设计时考虑数据驻留和留存灵活性 |
