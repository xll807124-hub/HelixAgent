## 一、威胁目录速查（15 项，下游 SEC 专项必须引用，不得自建威胁 ID）

| 威胁ID | 攻击目标/场景 | 主要影响 | 归属专项 |
|---|---|---|---|
| **T01** | 身份伪造/Token 滥用 | 未授权任务/代码操作 | SEC-002（身份）/SEC-005（凭据） |
| **T02** | 水平/垂直越权、混淆代理 | 跨仓库/组织泄露或变更 | SEC-002（授权）/SEC-003（策略） |
| **T03** | 直接/间接提示注入 | 越权工具调用、数据外传、恶意代码 | SEC-003（策略）/SEC-006（注入防护） |
| **T04** | 敏感数据外发 | L3/L4 泄露、合规事件 | SEC-004（沙箱）/SEC-005（凭据）/SEC-008（多租户） |
| **T05** | 凭据泄露 | 仓库/云服务被接管 | SEC-005（凭据代理）/SEC-008（数据治理） |
| **T06** | 沙箱逃逸与宿主访问 | 横向移动、宿主/租户失陷 | SEC-004（沙箱隔离基线） |
| **T07** | 危险命令/恶意代码写入 | 代码完整性、构建链受损 | HAR-001（工具治理）/SEC-003（策略） |
| **T08** | 第三方依赖/镜像/CI 供应链攻击 | 运行环境或产物被控制 | SBOM + 锁版本 + 漏洞监控（SEC-001 §9 规定范围） |
| **T09** | MCP/工具连接器越权或被替换 | 外部系统读写与数据外泄 | SEC-007（MCP治理）/HAR-005（路由） |
| **T10** | 跨租户数据混淆 | 多组织数据泄露 | SEC-008（多租户数据治理） |
| **T11** | 资源耗尽/拒绝服务/费用滥用 | 可用性下降、成本失控 | 预算/速率限制/熔断 + KillSwitch |
| **T12** | 事件/日志/审计证据被遗漏/篡改 | 事件无法调查、合规证据不足 | RT-003（事件）/OBS-001/002/007（遥测/审计） |
| **T13** | 记忆/索引/缓存投毒 | 持续错误决策或指令执行 | MEM（生命周期）/CTX（增量一致性） |
| **T14** | 计划审批前产生副作用 | 人类审批失去保护作用 | SEC-003（策略审批）/RT-002（状态机 WAITING_APPROVAL） |
| **T15** | 隐私/数据驻留/留存不当 | 法律、合同和信任损害 | SEC-008（数据治理）/GDPR 合规映射 |

### 下游引用原则

- 每个下游专项必须在设计文档中明确声明覆盖了哪些威胁 ID，不能遗漏 T08/T12/T13/T14 等"系统层"威胁。
- 不能用 SEC-001 §16 的 8 项待确认问题作为安全控制的豁免依据。
- T03（提示注入）没有单一防御手段，必须在 SEC-003（策略）、SEC-006（注入防护）、HAR-001（工具治理）和 CTX（不可信来源标记）之间建立纵深防御。

## 二、风险评分口径速查（SEC-001 §6，下游专项在设计"失败严重性"时必须复用）

### 评分公式

```
R = I（影响 1-5）× L（可能性 1-5）
风险等级：1-4 Low | 5-9 Medium | 10-16 High | 17-25 Critical
```

### 影响评分含义

| 分值 | 含义 |
|---|---|
| 1 | 极低：影响可忽略，或需要极不现实的条件 |
| 2 | 低：影响有限，攻击条件不常见 |
| 3 | 中：造成可恢复的业务/数据影响，存在现实攻击路径 |
| 4 | 高：严重数据或服务影响，攻击路径较现实 |
| 5 | 极高：重大机密/完整性/可用性/合规影响，或攻击易规模化 |

### 风险接受阈值（下游安全设计必须遵守的决策链）

| 等级 | 是否可接受 | 审批层级 | 后续要求 |
|---|---|---|---|
| **Low** | 可接受 | 部门负责人 | 记录风险、范围、责任人和复审日期 |
| **Medium** | 有条件接受 | 安全团队 + 业务负责人联合审批 | 有责任人、期限和验证条件的缓解计划 |
| **High** | 不可接受 | 风险管理决策层（CTO/CISO）+ 管理层双重审批 | 书面受益-风险分析 + 临时停止/限制措施 |
| **Critical** | 不可接受 | 同上 + 明确停止/限制功能的临时措施 | 书面受益-风险分析 + 停止条件 |

### 下游设计时的"硬性规则"

1. **控制有测试/运行证据才能用于残余风险重评** —— 不能以"有控制"直接减分。
2. **分值用于排序和决策支持，不替代专业判断** —— 不能把风险矩阵分值作为唯一的通过/拒绝依据。
3. **所有残余风险接受必须书面归档**：包含场景、固有/残余评分、业务理由、控制与缺口、影响范围、审批人、有效期、复审触发条件及到期处理。

## 三、数据分级速查（SEC-001 §5.2，下游所有涉及数据分类的组件必须引用）

| 级别 | 名称 | 定义 | 典型内容 |
|---|---|---|---|
| **L1** | 公开级 | 泄露无危害 | 经授权公开发布的信息 |
| **L2** | 内部级 | 泄露造成一般危害 | 非公开但影响有限的内部资料 |
| **L3** | 敏感级 | 泄露造成严重危害 | 私有源代码、未公开漏洞信息 |
| **L4** | 机密级 | 泄露造成特别严重危害 | 凭据、密钥、敏感个人信息 |

### 定级规则（必须在下游组件的数据流中遵守）

1. **混合数据按最高级别**：不能对不同级别数据使用同一保护强度。
2. **聚合/摘要/嵌入/缓存/日志/备份不得低于来源最高级别** —— CTX 索引向量、MEM embedding、日志脱敏前的内容均须遵守此规则。
3. **敏感个人信息不低于 L4**。
4. **级别可动态上调，下调必须经数据责任人和安全团队审批**。

## 四、MVP 控制基线速查（SEC-001 §8，下游专项必须覆盖的 9 项基线）

| 编号 | 控制领域 | 下游专项归属 | 关键要求摘要 |
|---|---|---|---|
| **B1** | 身份与授权 | SEC-002/003 | 强认证传输、任务+仓库范围授权、默认拒绝、每个敏感 Action 重检授权、可审计 |
| **B2** | 数据分级 | SEC-008/CTX-005/MEM-001 | L1-L4 贯穿上下文/模型路由/存储/日志/备份/导出/删除 |
| **B3** | Agent 防护 | SEC-003/006 | 所有仓库/Issue/网页/工具/模型返回按不可信数据处理；高风险操作需策略校验+人工确认 |
| **B4** | 执行隔离 | SEC-004 | Docker 非特权 + Seccomp 默认策略 + 禁用 CAP_SYS_ADMIN + 网络默认拒绝 |
| **B5** | 凭据 | SEC-005 | Agent/Worker 不持有长期凭据；短期/任务作用域凭据由受控服务提供并可撤销 |
| **B6** | 第三方依赖 | SBOM 专项 | SBOM 可追溯、版本锁定、禁止 latest、漏洞监控、关键依赖哈希/签名校验 |
| **B7** | 代码交付 | HAR-001/EVA-006 | 变更经测试+扫描、PR 必须人工审查、Agent 不自动合并 |
| **B8** | 审计与响应 | OBS-001/002/007 | 关键操作可关联审计证据；提供任务/工具级暂停与凭据撤销路径 |
| **B9** | 红队上线门禁 | EVA-006 | MVP 发布前执行 §10 测试用例；高风险失败阻塞上线 |

## 五、对下游各专项的具体接口契约

| 下游专项 | 必须复用的 SEC-001 坐标 | 禁止事项 |
|---|---|---|
| **SEC-002** 授权/RBAC | T01/T02 威胁、数据分级（L1-L4）、B1 控制基线、Token 滥用路径 | 不能把能力声明当成授权结果 |
| **SEC-003** 策略网关 | T02/T03/T14 威胁、风险评分口径（High/Critical 必须有缓解计划）、审批矩阵 | 不能跳过风险接受审批流程 |
| **SEC-004** 沙箱隔离 | T04/T06 威胁、B4 控制基线（Docker 非特权/Seccomp/能力最小化/网络默认拒绝）、SEC-001 §8.2 容器基线清单 | 不能用特权容器或 CAP_SYS_ADMIN |
| **SEC-005** 凭据代理 | T01/T05 威胁、B5 控制基线（无长期凭据、短期可撤销凭据、禁止未筛选 env 继承） | Agent 内存/环境变量不能保存 L4 凭据 |
| **SEC-006** 提示注入防护 | T03/T14 威胁、B3 控制基线（不可信数据处理）、T04 数据外传路径 | 不能把模型拒答能力作为唯一防护层 |
| **SEC-007** MCP 连接器治理 | T09 威胁（连接器越权/被替换）、B1/B5 凭据+授权基线 | 不能信任未白名单的连接器身份/Schema |
| **SEC-008** 多租户数据治理 | T10 威胁（跨租户混淆）、L1-L4 定级规则（聚合/摘要/缓存不得低于来源级别） | 缓存/索引/日志不得跨租户泄露 |
| **SEC-009** KillSwitch | T11 威胁（资源耗尽/DoS）、B8 审计基线 | Kill Switch 操作本身必须有审计证据 |
| **HAR-001** Harness | T07（危险命令写入）、B7（PR 必须人工审核） | Harness 不能绕过 Agent 的策略校验 |
| **HAR-005** 统一路由 | T09（MCP 连接器越权）、T07（工具过度授权） | 路由决策不能脱离 RBAC 授权上下文 |
| **OBS-004/007** 遥测/审计 | T12（证据被遗漏/篡改）、B8（审计与响应）、L1-L4（审计数据分级） | 审计日志本身不得包含未脱敏 L3/L4 内容 |
| **EVA-006** 发布门禁 | §10 红队测试用例（8 个场景）、高风险失败阻塞上线原则 | 安全结果不能被效率/速度指标抵消 |
| **CTX-001** 索引 | L1-L4（索引向量不得低于来源级别）、T13（记忆/索引投毒路径） | 索引内容不得包含未脱敏凭据 |
| **MEM-001** 记忆 | L1-L4（embedding/摘要不得低于来源级别）、T13（记忆投毒） | 记忆不得包含凭据/密钥/模型思维链 |

## 七、版本与复评触发条件

SEC-001 v0.1-designed 发生以下情形时触发复评：
- 架构/信任边界/模型或工具重大变更
- 新增数据类别、租户或外部连接器
- 高危漏洞或安全事件
- 控制测试失败
- 法规/合同/供应商条件变更
- 至少按季度复核一次
