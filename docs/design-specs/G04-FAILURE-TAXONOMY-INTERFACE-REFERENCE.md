## 一、MVP 症状词表速查（13 项，下游必须复用，不得自建失败类别）

| 症状类别 | 代码 | 观测边界 | 默认处置基线 | 归属专项 |
|---|---|---|---|---|
| **瞬时连接故障** | `TRANSIENT_CONNECTIVITY` | 连接建立或传输层明确失败，且证据表明请求未被远端接受 | 交由 REL-002/003 判定重试；本分类器不授权重试 | REL-002 RetryPolicy |
| **依赖限流** | `DEPENDENCY_THROTTLED` | 明确限流/容量信号，含服务端等待建议 | 交由 REL-002/003；不得忽略服务端建议 | REL-002/003 熔断 |
| **依赖不可用** | `DEPENDENCY_UNAVAILABLE` | 外部依赖明确暂时不可用，或健康探测确认不可用 | 交由 REL-002/003；考虑依赖级熔断 | REL-003 熔断 |
| **请求被拒绝** | `REQUEST_REJECTED` | 请求被明确拒绝或参数/契约校验失败 | 默认不重试；需责任模块处理输入/认证/授权 | SEC-002/003 授权 |
| **操作超时** | `OPERATION_TIMED_OUT` | 操作超时，但请求是否已被接受/产生副作用尚不确定 | 默认禁止盲重试；先对账确认结果（RT-007） | REL-007 幂等 |
| **执行中止** | `EXECUTION_ABORTED` | Worker/沙箱/工具/进程被终止，或执行未正常完成 | 暂停受影响步骤并保留现场；恢复语义由 REL-005/SEC-009 定义 | REL-005 恢复 |
| **结果无效** | `RESULT_INVALID` | 返回结果不符合约定结构、无法解析或缺少必需证据 | 不把无效结果当成功；转交适配器/验证流程 | HAR-001 工具治理 |
| **任务验证失败** | `TASK_VALIDATION_FAILED` | 测试/构建/扫描/业务验收工具成功执行并给出明确未通过结果 | 不作为基础设施重试；进入诊断/修复流程 | REL-008 测试失败 |
| **状态或存储完整性失败** | `STATE_OR_STORAGE_INTEGRITY_FAILED` | 事件/检查点/工作区/持久化完整性/一致性校验失败 | Fail-closed，暂停并升级；不自动覆盖证据 | RT-006/007 状态 |
| **资源限制达到** | `RESOURCE_LIMIT_REACHED` | 任务/组织预算/配额/容量或执行资源上限明确触发 | 停止消耗对应资源并告知责任方；不得通过重试规避 | 预算/速率限制 |
| **安全控制阻断** | `SAFETY_CONTROL_BLOCKED` | 观测到 Policy Gateway 或安全控制阻断 | 分类器只记录初筛；最终判定归 SEC；禁止改成可重试 | SEC-003 策略网关 |
| **用户或审批停止** | `USER_OR_APPROVAL_STOP` | 用户取消/暂停，或流程因等待审批而停止 | 尊重用户/审批状态；不是系统故障，不进入自动重试 | RT-002 状态机 |
| **未知失败** | `UNKNOWN_FAILURE` | 证据不足、检测器不匹配、信号冲突无法安全消解，或新失效模式 | 终止当前失败步骤、处置升级、保全现场；绝不默认为 retryable | REL-009 故障注入 |

### 下游引用原则

1. **症状分类是失败观测，不等同于 Action/Task 最终状态** —— 不能用症状直接规定恢复点。
2. **禁止扩张稳定枚举** —— 新增/弃用症状需版本化评审；检测器插件不可自行创建稳定症状类别。
3. **`UNKNOWN_FAILURE` 的处置基线不可放宽** —— 组织级配置只允许更严格处置（更早暂停、更高等级通知），不允许设置为默认继续/默认成功/自动重试。

## 二、三维正交分类模型速查（REL-001 §2.1，下游分析/指标时必须遵守）

```
一个失败 = 症状维度（可观测） × 阶段维度（显现位置） × 根因维度（致因归属）
```

| 维度 | 基数 | MVP 状态 | 下游使用规则 |
|---|---|---|---|
| **症状维度** | 13 项（固化） | 稳定契约 | dedup_key、告警聚合、快速止血 |
| **阶段维度** | 候选（未冻结） | 框架确立，词表保持候选 | 可记录但不可作为唯一分类依据 |
| **根因维度** | 候选（可修订） | 初始为未知，允许事后修订 | 不得用于实时决策，仅用于事后归因分析 |

**三者关系**：
- 某个症状可由多个根因引起；一个根因可表现为多个症状（多对多）。
- 聚合和 dedup_key 只使用低基数症状类别及必要的稳定范围，不使用自由文本、路径、请求 ID 或根因描述。
- 症状是首次分类时的运行事实，原则上不可静默改写；根因是可审计的分析结论，允许后续修订。

## 三、检测器注册与分类逻辑速查（REL-001 §5）

### 3.1 初筛 8 步流程

```
1. 采集并绑定失败发生时的 Task/Workflow/Worker/Action/Trace 和来源组件
2. 规范化结构化信号，应用脱敏、长度和基数限制
3. 先识别强制停止信号（用户停止/安全阻断/资源上限/状态完整性）
4. 运行匹配的检测器；基于结构化证据匹配症状
5. 检测器冲突时保留各检测结果及证据；无法安全裁决时输出 UNKNOWN_FAILURE
6. 计算校准置信度分数，映射到外层决策档位
7. 生成版本化分类事件；对于 UNKNOWN 执行终止/升级/保全
8. SEC 相关信号通过事件引用交由安全控制面作最终判定
```

**硬性规则**：
- 强制停止信号（用户停止/明确安全阻断/资源上限/状态完整性）不得被低优先级规则覆盖。
- 检测器冲突且无法按契约安全裁决时，必须输出 `UNKNOWN_FAILURE`，不可任选较宽松结论。
- MVP 不将 LLM/机器学习裁判用于自动放宽处置；若引入辅助分类器，其输出只能作为有来源、可校准、可审计的候选证据。

### 3.2 检测器插件治理约束

| 检测器义务 | 下游专项约束 |
|---|---|
| 声明所属组件、支持的症状、输入信号范围、版本、优先级 | HAR-001 工具适配器必须注册检测器 |
| 声明置信度校准状态、失败模式和维护责任 | REL-009 故障注入必须测试检测器退化 |
| 不可自行创建稳定症状类别 | 所有新症状必须走 REL-001 版本化评审 |
| 不能绕过 SEC 判定或未知失败的终止基线 | SEC-003 策略网关结果不得被分类器覆盖 |

## 四、置信度双层机制速查（REL-001 §6）

```
内层校准分数（分类器对候选症状判断的校准概率/分数）
    ↓ 映射
外层决策档位（根据经验证的决策阈值和风险规则）
```

| 层级 | 用途 | 禁止事项 |
|---|---|---|
| **内层校准分数** | 评估与分析，记录校准方法/数据版本 | 不直接赋予执行权限；没有校准证据时标记为未校准，不伪造分数 |
| **外层决策档位** | 自动采纳/需额外核验/需人工判定 | 未知结果保持 UNKNOWN，不得因为分数高或配置变化被改判为安全可重试 |

**风险规则**：
- 当分类错误可能导致安全边界放宽、重复副作用或下游雪崩时，采用保守档位。
- 校准质量按症状类别、检测器、来源和版本分层评估，关注校准误差以及高风险类别的漏判率。

## 五、`UNKNOWN_FAILURE` 处置基线速查（REL-001 §7，下游专项不得放宽）

### 5.1 不可放宽的处置基线

```
1. 停止失败 Action 的自动继续/重试
2. 冻结相关副作用边界，按 RT-007 对不确定外部结果进行对账
3. 保留必要事件/Trace 和现场证据
4. 升级给对应责任团队或人工
5. 在分类系统恢复或人工明确处置前不自动标记成功
```

**组织级配置约束**：只允许更严格处置（更早暂停、更高等级通知、更严格证据保全），不允许设置为默认继续/默认成功/自动重试。

### 5.2 `unknown_rate` 一级健康指标

```
unknown_rate = UNKNOWN 失败数 / 可分类失败总数（规定时间窗内）
```

| 指标项 | 要求 | 下游专项 |
|---|---|---|
| SLO 设置 | 必须设置 SLO、告警阈值和评审责任；数值阈值需通过基线数据和评测集确定 | OBS-003 指标 |
| 告警触发 | 超阈值告警需触发检测器退化/新失效模式调查 | OBS-005 告警 |
| 受控聚合 | 按来源组件、检测器版本、症状候选和组织范围提供 | OBS-003 指标 |
| 禁止伪造零值 | 无失败样本的窗口不计算为零，应标记无样本 | OBS-003 指标 |

## 六、安全归属边界速查（REL-001 §8）

```
失败分类器（本组件）          SEC 模块（安全专项）
    ↓                            ↓
  采集与初筛                  威胁归类与授权判定
  记录观测症状                  风险升级与响应
  标记需要 SEC 判定              最终安全真相
    ↓                            ↓
  共享运行时事件与引用耦合
```

| 职责 | 失败分类器（G04） | SEC 模块（SEC-001/003） |
|---|---|---|
| **可做** | 采集、规范化、初筛；记录观测到的症状和证据引用；标记需要 SEC 判定 | 威胁归类、授权/策略判定、风险升级、安全响应 |
| **不可做** | 不自行批准、拒绝或改变授权；不复制策略逻辑 | 不能被分类器的初筛结论覆盖 |

**关联机制**：
- SEC 判定结果作为可关联的独立事实写入其权威事件/审计来源。
- 失败分类事件与 SEC 事件通过 Trace/Action/Worker ID 关联，不在两个模块各自维护互相矛盾的安全真相。

## 七、对下游各专项的具体接口契约

| 下游专项 | 必须复用的 G04 坐标 | 禁止事项 |
|---|---|---|
| **REL-002** RetryPolicy | 13 项症状词表、TRANSIENT_CONNECTIVITY/DEPENDENCY_THROTTLED/DEPENDENCY_UNAVAILABLE 初筛结果 | 不得仅凭根因猜测重试；OPERATION_TIMED_OUT 禁止盲重试 |
| **REL-003** 熔断 | DEPENDENCY_UNAVAILABLE/DEPENDENCY_THROTTLED 症状、检测器版本 | 不得把 UNKNOWN_FAILURE 当成可熔断的依赖故障 |
| **REL-004** Checkpoint | STATE_OR_STORAGE_INTEGRITY_FAILED 症状、现场保全要求 | Checkpoint 完整性失败不得自动覆盖证据 |
| **REL-005** 恢复决策 | EXECUTION_ABORTED 症状、阶段维度（候选）、独立根因分析 | 恢复决策不能只依赖症状维度 |
| **REL-007** 幂等 | OPERATION_TIMED_OUT 症状、不确定副作用结果对账要求 | 幂等引用不能缺失时默认可重试 |
| **REL-008** 测试失败 | TASK_VALIDATION_FAILED 症状、测试工具异常信号映射 | 不得建立冲突的症状枚举 |
| **REL-009** 故障注入 | 分类冲突、未知失败、版本映射、检测器退化测试场景 | AgentChaos 不得注入会被误判为正常的故障 |
| **EVA-004** 失败归因 | 稳定症状做运行统计、可修订根因做归因分析、分类版本 | 归因分析必须保留当时分类版本 |
| **HAR-001** 工具治理 | RESULT_INVALID 症状、工具结果解析器注册表 | 工具适配器必须注册检测器并声明支持的症状 |
| **SEC-001** 威胁模型 | SAFETY_CONTROL_BLOCKED 症状、SEC 判定引用/待判定标记 | 威胁归类不能与症状分类混淆 |
| **SEC-003** 策略网关 | SAFETY_CONTROL_BLOCKED 症状、REQUEST_REJECTED 症状、SEC 归属边界 | Policy Gateway 决策不得被分类器改判 |
| **OBS-002** 事件 Schema | 分类结果事件字段（症状类别、分类版本、检测器版本、置信度、阶段、根因、SEC 引用） | 事件字段必须遵守 RT-003 版本策略 |
| **OBS-003** 指标 | unknown_rate、检测器调用耗时、信号冲突率、根因修订率、分类版本分布 | unknown_rate 不能被忽略或隐藏 |

## 八、版本持久化与历史转换规则（REL-001 §4.3）

### 8.1 版本持久化硬性要求

```
每条失败事件必须持久化：
□ 分类体系版本（如 taxonomy.v1.2）
□ 产生该结论的检测器版本（如 detector-http.v2.3）
```

### 8.2 版本升级不回写历史

```
禁止：
- 版本升级时回写或全量重分类历史事件
- 把新旧版本映射关系伪造成等价

必须：
- 分类词表或规则变更时，发布明确的新旧版本映射及映射有效范围
- 分析层可按指定口径转换和比较，保留原始版本结果、转换版本和转换依据
- 无法无损映射的历史类别必须标为不可比/未映射
```

### 8.3 原始事实不可变

```
原始事件及原始分类事实保持不可变；分析转换是派生视图。
```

## 九、性能与可观测性约束（REL-001 §9）

### 9.1 性能目标（待评测后冻结）

| 指标 | 目标范围 | 说明 |
|---|---|---|
| 分类耗时 | MVP 初筛应由本地确定性检测器完成 | 不为每次失败强制增加模型调用 |
| 检测器调用耗时 | 需可观测 | 分层报告各检测器耗时 |
| 未校准结果比例 | 需可观测 | 标记为未校准的分类占比 |
| 信号冲突率 | 需可观测 | 检测器冲突次数 / 总失败数 |
| unknown_rate | 需设置 SLO | 阈值通过评测后冻结 |
| 根因修订率 | 需可观测 | 修订次数 / 总失败数 |

### 9.2 根因修订审计要求

```
每次根因修订必须记录：
□ 旧值（old_root_cause）
□ 新值（new_root_cause）
□ 依据（evidence_reference）
□ 操作者/分析器（actor_id / analyzer_id）
□ 修订时间（revised_at）
```

## 十、验收标准摘要（REL-001 §10，下游专项设计前必须满足）

| 编号 | 验收标准 | 下游验证方 |
|---|---|---|
| 1 | 每个 MVP 症状类别有边界说明、正向信号、反例/歧义边界及测试样本 | REL-009 故障注入 |
| 2 | 阶段和根因不会被混入症状枚举 | 所有下游专项 |
| 3 | 对同一输入和同一检测器/分类版本，分类结果可复现 | REL-009 故障注入 |
| 4 | UNKNOWN 在所有默认和组织级配置下均不会自动继续/成功/重试 | REL-002/003 |
| 5 | UNKNOWN 能触发现场保全、处置升级和 unknown_rate 计量 | OBS-003/005 |
| 6 | 每条分类事件持久化分类版本和检测器版本；历史事件不被新词表批量改写 | OBS-002 事件 |
| 7 | 新旧词表映射可在分析层查询，转换过程保留原分类、目标口径和映射依据 | OBS-002 事件 |
| 8 | 症状与根因分离：dedup_key 不包含可变根因；根因可修订且修订留有完整审计记录 | OBS-002 事件 |
| 9 | 检测器插件不能扩张稳定枚举、改变 unknown 处置或绕过 SEC 判定 | HAR-001 工具治理 |
| 10 | SEC 归属信号有事件关联路径；失败分类器不能自行作出授权放行或安全风险终判 | SEC-003 策略网关 |
| 11 | 分类事件与指标符合租户隔离、脱敏、低基数和留存要求 | OBS-004 脱敏 |
| 12 | 以标注数据评估分类表现、校准质量和 unknown_rate；具体准确率/延迟/容量/SLO 阈值由 EVA 基线及跨模块评审冻结 | EVA-004 失败归因 |
