## 二、REQ-EVA-007 核心设计内容

### 2.1 设计目标

补齐评估体系从"发布前质量门禁"（REQ-EVA-001~006）到"生产态持续反馈"的结构性缺口。

### 2.2 核心功能模块

| 模块 | 功能 | 关键设计 |
|------|------|---------|
| **生产漂移检测** | 检测模型供应商侧更新、数据分布变化导致的能力退化 | 四维漂移信号：任务成功率、Regression eval、模型行为、评估集老化 |
| **失败案例闭环** | 生产失败自动反哺 Golden Dataset | 四道入集闸门：新颖性、可复现性、可判定性、污染检查 |
| **Dataset 动态更新** | 评估集与生产分布保持对齐 | Capability eval → Regression suite 转换规则 |
| **版本回滚机制** | 数据驱动的模型/评估集版本回滚 | 回滚触发矩阵 + Bundle 管理 |

### 2.3 行业对标

| 标杆 | 借鉴点 |
|------|--------|
| **Anthropic** | 《Demystifying evals for AI agents》评估方法分阶段部署（Pre-launch vs Post-launch） |
| **MLflow** | Model Registry 版本管理与回滚机制 |
| **SWE-bench** | Capability → Regression 转换机制 |

## 四、设计亮点

### 4.1 架构亮点

1. **非侵入式采集**：复用 REQ-OBS-002 审计事件，无需新增独立采集基础设施
2. **模块化设计**：漂移检测、失败闭环、Dataset 更新、版本回滚四大模块职责清晰
3. **灵活阈值配置**：支持按血缘类型、触发器类型差异化配置

### 4.2 工程亮点

1. **与 REQ-EVA-006 无缝集成**：扩展现有四级门禁，新增第五级"生产漂移检测门禁"
2. **完整的回滚决策算法**：基于多维度评分（漂移信号 + 通过率 + 用户反馈 + Kill Switch）
3. **版本 Bundle 管理**：模型版本 + 评估集版本 + 评分器版本统一管理

### 4.3 合规亮点

1. **数据隐私保护**：失败案例必须脱敏，PII 自动检测
2. **审计追踪完整**：漂移检测记录、回滚事件记录均可追溯
3. **留存策略对齐**：与 REQ-OBS-007 审计留存策略一致
