## 2. 执行摘要与功能目标

建立可路由、多后端、策略驱动的 Agent 沙箱能力，使模型生成的代码、命令和工具执行处于独立且可审计的执行边界。沙箱后端通过统一的概念能力契约接入；控制平面依据多维隔离触发矩阵选择后端和隔离配置。隔离需求只可维持或升级，不得因后端缺货、性能、成本或用户选择而静默降级。

安全核心不变量：

1. 控制平面持有策略、身份、凭据和沙箱编排权；执行平面只获得完成任务所需的工作区及能力。
2. 文件系统、网络、进程/系统调用、资源和租户边界分别执行最小权限；任何单一控制都不替代其他控制。
3. 外部网络目的地来自已登记连接器的声明，经审批固化为不可变版本，再由运行时下发；平台不预置通用域名白名单。
4. 沙箱内不放置长期凭据或可复用根凭据。外部连接需要身份时优先由边界代理按已批准连接器与操作注入短期、任务/操作范围凭据；具体签发与撤销服从 `REQ-SEC-005`。
5. 沙箱及其镜像、策略、连接器清单、租户、Task、Worker、Action、Trace 和代码 revision 均可关联追溯。
6. 安全门禁优先于可用性和成本优化。无法满足所需隔离能力时拒绝启动或暂停任务，升级至有能力的后端，不能自动降级。

**价值**：限制提示注入、恶意依赖和模型错误的影响范围；在可验证的约束内运行代码；使环境启动时间、池容量与成本可通过 SLO 运营，而不以安全边界换取性能。

## 3. 范围、边界与问题分析

### 3.1 范围

- 沙箱后端抽象和能力声明、后端注册与策略路由。
- 云端生产隔离执行、开发/测试环境的策略抽象及平台能力声明。
- 隔离级别和多维触发矩阵、硬性升级/禁止降级规则。
- 文件系统、网络出口、进程、资源、凭据、租户、镜像和生命周期控制。
- 连接器目的地声明、审批版本固化、运行时下发与变更审计。
- SLO 驱动的自适应 WarmPool、审计留存分档及查询 SLA。
- 安全验证、性能/容量/成本基准、可观测性及故障处置要求。

### 3.2 非目标

- 本需求不实现沙箱后端、策略引擎、网络代理、连接器、凭据代理或池控制器。
- 不选定唯一云厂商、容器运行时或微虚拟机实现；这些属于能力适配和部署评审。
- 不把模型拒绝、提示词约束或人工审批作为 OS/虚拟化隔离的替代。
- 不定义 MCP Server 内部隔离实现；连接器身份与授权由 `REQ-SEC-007` 细化，本需求定义其执行边界要求。
- 不将快照/恢复当作安全隔离证明；快照只可在策略、身份、租户和密钥边界重新验证后恢复。

### 3.3 当前设计缺口及其影响

原有草案已包含多级隔离、两阶段执行、文件/网络/资源控制、审计和测试方向，但有以下需收敛之处：

| 缺口或冲突 | 影响 |
|---|---|
| 以固定技术和平台列表描述沙箱，而缺少后端能力契约和路由职责 | 供应商或运行时绑定，无法按真实威胁、平台能力及成本做替换 |
| 把 `risk_level` 直接映射到隔离等级 | 风险评分维度被压扁；数据敏感度、来源信任、租户暴露和任务副作用可能不一致 |
| 固定预置网络域名白名单 | 目的地容易过宽、过期或与真实依赖不符；审批来源和变更责任不清 |
| 将凭据注入 Setup 沙箱表述为默认做法 | 与 `SEC-005` 的凭据代理及“不暴露根凭据”原则产生歧义 |
| 同时承诺 Linux、macOS、Windows 原生生产隔离 | OS 安全原语不等价，Windows 审计/维护面增加且难以提供相同保证 |
| WarmPool 固定实例数 | 不能针对实际分配延迟和到达率调优，存在冷启动违约或闲置成本 |
| 审计日志统一留存时长，未分用途、可检索性和删除级联 | 运营调查、合规保留、隐私删除之间可能冲突 |
| 把未测量的冷启动目标作为通用保证 | 不同后端/镜像/区域负载差异可能导致虚假 SLA |

设计将把技术选择从静态配置提升为可解释的策略决策，并明确失败时安全优先的行为。具体风险权重、成本预算和法律保留期限需由架构、安全、SRE、合规和租户治理责任人依据部署环境冻结。

## 4. 行业参考与设计依据

研究日期：2026-09-23。下列“公开事实”仅表示官方/公开来源陈述了对应能力；不表示对其实现进行独立验证，也不表示本项目已采用或可直接复制其产品实现。设计建议均标为“推断/建议”。

### 4.1 OpenAI Codex

- **定位与相关能力（公开事实）**：Codex 是带有 Harness、工具执行和任务事件流的编码 Agent；Codex Web 在 worker 提供的容器工作区内运行 App Server，客户端可通过服务端事件流查看长期任务。
- **隔离设计（公开事实）**：OpenAI 关于安全运行 Codex 的资料描述沙箱和审批共同确定文件、网络和越界操作边界；受管网络限制预期目的地，对不熟悉目的地要求审批。公开资料不支持把其云端生产隔离后端一概断言为某种微 VM 技术。
- **实现逻辑**：执行请求经 Harness 和策略边界转为沙箱命令；越界请求进入审批/自动审查；执行事件持续提供 UI 和审计所需进度。
- **算法亮点**：用确定性权限边界控制文件和网络，审批层决定越界行为，不依赖模型自我约束。
- **可借鉴点（推断）**：把隔离强制和审批判定分开；后端能力不明时不推断具体基础设施；将生命周期事件作为长任务可恢复与可观测的基础。
- **来源**：[Running Codex safely at OpenAI](https://openai.com/index/running-codex-safely/)、[Unlocking the Codex harness](https://openai.com/index/unlocking-the-codex-harness/)。访问日期：2026-09-23。

### 4.2 GitHub Copilot Cloud Sandbox

- **定位与相关能力（公开事实）**：Copilot Cloud Sandbox 为 Copilot CLI 提供云端隔离执行环境；官方文档称其基于 Azure Container Apps Sandboxes，GitHub 提供身份、策略和计费层。
- **隔离设计（公开事实）**：会话使用独立、短生命周期 Linux 环境；Azure 公开资料介绍硬件隔离微 VM、出站策略、资源和生命周期管理能力。具体能力可受预览状态、区域及服务配置限制。
- **实现逻辑**：组织策略启用后创建会话级环境，复用既有身份和策略，运行完成后按生命周期回收。
- **算法亮点**：把身份/策略控制面与执行计算边界分层；隔离会话避免不同运行共享本地状态。
- **可借鉴点（推断）**：将短生命周期执行单元、租户策略和策略审计绑定；抽象能力而非绑定具体 Azure 产品。
- **来源**：[About cloud and local sandboxes for GitHub Copilot](https://docs.github.com/en/copilot/concepts/about-cloud-and-local-sandboxes)、[Azure Container Apps Sandboxes](https://learn.microsoft.com/en-us/azure/container-apps/sandboxes-overview)。访问日期：2026-09-23。

### 4.3 Anthropic Claude Code

- **定位与相关能力（公开事实）**：Claude Code 提供本地编码 Agent 和托管云会话；可在适当隔离环境中执行 Bash、工具和扩展。
- **隔离设计（公开事实）**：文档区分文件系统与网络隔离；本地可利用 OS 沙箱，云端使用独立虚拟化环境；单独限制 Bash 不等于把文件工具、Hook 和 MCP 整体纳入边界。文档亦披露网络代理默认不检查 TLS 内容等限制。
- **实现逻辑**：沙箱在 OS 或虚拟化层强制路径、进程和出站边界；需更强保证时把整次 Agent 会话放入外层容器/VM。
- **算法亮点**：减少逐命令审批的同时，让操作系统边界持续生效；通过分层沙箱降低权限提示疲劳。
- **可借鉴点（推断）**：明确执行边界覆盖范围及已知限制；网络白名单不是 TLS 内容检查；生产无人值守不应只沙箱 Bash 子进程。
- **来源**：[Claude Code sandboxing](https://www.anthropic.com/engineering/claude-code-sandboxing)、[Sandboxing documentation](https://code.claude.com/docs/en/sandboxing)、[Sandbox environments](https://code.claude.com/docs/en/sandbox-environments)。访问日期：2026-09-23。

### 4.4 Microsoft Azure SRE Agent 与 ACA Sandboxes

- **定位与相关能力（公开事实）**：SRE Agent 用于运维任务；Azure Container Apps Sandboxes 面向隔离、短生命周期或可暂停恢复的 Agent 工作负载。
- **隔离设计（公开事实）**：微软公开资料描述推理/编排与模型编写工具的执行分离、每 Agent 微 VM、默认拒绝出口和代理边界；凭据可由边界服务按调用注入而不驻留执行 VM。ACA Sandboxes 文档描述按组管理的生命周期、网络及资源能力。
- **实现逻辑**：控制运行时通过窄接口指挥隔离执行环境；所有出站请求在外部边界校验，凭据服务依据目的地和操作策略提供凭据。
- **算法亮点**：请求在代理处绑定目标、操作与调用，失败时拒绝而不把凭据交回沙箱；隔离与凭据安全分层。
- **可借鉴点（推断）**：将连接器审批版本、出口请求和凭据授予绑定；用能力路由适配不同强度后端。
- **来源**：[Azure SRE Agent security overview](https://learn.microsoft.com/en-us/azure/sre-agent/security-overview)、[Restrict the environment](https://techcommunity.microsoft.com/blog/appsonazureblog/stop-restricting-the-agent-start-restricting-its-environment-/4548726)、[Azure Container Apps Sandboxes](https://learn.microsoft.com/en-us/azure/container-apps/sandboxes-overview)。访问日期：2026-09-23。

### 4.5 Cursor

- **定位与相关能力（公开事实）**：Cursor 提供 IDE 编码 Agent 和云端 Agent；公开材料涵盖本地操作系统沙箱和云端隔离执行。
- **隔离设计（公开事实）**：官方资料描述本地不同操作系统的沙箱原语及云端隔离环境，并通过配置控制文件和网络访问。
- **实现逻辑**：将用户级/工作区策略应用到操作边界，执行工具受限于工作目录和网络策略。
- **算法亮点**：按平台采用本地原语，统一用户可理解的策略意图。

### 4.6 Google Jules

- **定位与相关能力（公开事实）**：Jules 是异步云端编码 Agent；公开文档描述隔离环境、仓库工作区和任务执行能力。

### 4.7 Cloud Security Alliance

- **定位与相关能力（公开事实）**：CSA 研究材料针对 Agentic AI、MCP 和编码 Agent 的最小权限与沙箱治理给出风险分层建议。
- **相关设计（公开事实）**：报告强调文件系统、网络、系统调用、工具能力、身份及审计共同构成边界；对更不可信输入和多租户执行提出更强隔离建议。
- **可借鉴点（推断）**：隔离选择应结合威胁和信任假设，不应把某种容器标签等同于安全证明；针对具体 workload 做安全和性能验证。

## 5. 已确认的设计决策

以下六项为用户明确决策，作为本版本设计输入。推导出的实施规则标为“设计要求”，需要在跨模块评审中冻结。

### 5.1 多后端抽象与风险路由（Q1）

- **用户决策**：隔离后端抽象化，由风险路由决定实例化哪个后端。
- **设计要求**：定义统一的概念能力契约，至少表达隔离边界类型、文件策略、网络策略、资源约束、生命周期、快照/恢复能力、审计能力、租户隔离能力和平台可用性。后端注册信息声明其能力、限制、版本、区域和可用容量；不能声称不具备的能力。
- **路由职责**：控制平面先算出最低所需隔离能力，再过滤不满足硬约束的后端，最后在合格候选中按可用性、延迟、资源成本及租户策略择优。选择结果和原因绑定本次 Task/Worker、策略版本及后端版本。
- **实施边界**：当前不预选 gVisor/Kata/Firecracker 或厂商服务为唯一实现；部署评审依据威胁模型和基准结果选出至少一个生产后端，并保留适配替换能力。

### 5.2 连接器声明驱动的网络策略（Q2）

- **用户决策**：不预设平台通用网络白名单；采用“连接器声明 → 审批固化 → 运行时下发”。
- **连接器声明**应包含用途、拥有者、环境、目标服务/域名或网络范围、端口/协议、所需操作和资源范围、数据级别、凭据需求、有效期、失败行为和验证方式。声明不等同于批准。
- **审批固化**：Policy Gateway/授权责任人校验声明与任务、租户、风险及数据策略；批准后产生不可变版本。任何目的地、范围、凭据或数据分类变更均生成新版本并重新审批；旧版本撤销后不得继续分配给新运行。
- **运行时下发**：Sandbox Router 仅下发与当前 Task/Worker 绑定的已批准连接器版本；网络代理逐请求校验目的地、协议、端口和调用身份。未声明、未批准、已过期或无法解析的目的地默认拒绝并留审计事件。
- **DNS/IP 防绕过要求**：目的地主体校验应覆盖 DNS 重绑定、CNAME 链、解析后的私网/回环/链路本地/云元数据地址、IPv4/IPv6 表示差异及重定向目标。仅做域名文本匹配不构成充分出口控制。TLS 内容检查能力及其合法性/性能影响由部署策略决定，不假定普通代理可检查加密载荷。

### 5.3 Level 3 多维触发、成本闸门、禁止降级（Q3）

- **用户决策**：触发矩阵正交于 `risk_level`，命中任一项即升级；同时设置成本闸门；禁止向下降级。
- `risk_level` 继续按 `REQ-SEC-001` 作为风险结果使用，但不单独决定隔离后端。路由输入至少包含：风险等级、数据分类、代码/依赖/Issue 等输入来源信任、租户隔离模式、任务写入/外部副作用能力、连接器和网络暴露、执行平台信任及后端实测能力。
- **触发矩阵**：安全/合规责任人对每个维度定义触发谓词及映射到最低隔离能力的规则。任一维度达到 Level 3 门槛即要求 Level 3 或更强能力。高风险级别不得被低敏数据维度抵消，多个维度也不得求平均抵消命中项。
- **成本闸门**仅能在满足最低隔离能力的候选后端中筛选，或拒绝/排队/请求有权限主体批准预算例外。成本闸门不得选择低于最低能力的后端；不能满足成本时返回明确的预算/容量阻塞，不执行。
- **单调升级**：任务生命周期内，隔离要求可因新输入、新数据、权限、连接器或安全事件提高；不得自动降低。若后端故障或容量不足，排队、拒绝或升级到满足要求的后端。降低只允许新建任务前经授权变更策略并重新评估；不得更改既有运行的有效边界。
- **待冻结**：各触发维度的具体阈值、成本预算数值、可批准预算例外的角色与审计字段需评审确定；未冻结前采取保守默认拒绝策略，不宣称已具备自动路由阈值。

### 5.4 审计留存分档、WORM、检索 SLA、删除级联（Q4）

- **用户决策**：按用途三档留存，结合 WORM、检索 SLA 和租户删除级联治理。
- **档位建议（用途分档，不等于具体天数）**：
  - **运行诊断档**：沙箱生命周期、资源、策略决策、网络阻断及故障诊断事件；用于一线排障和容量分析。
  - **安全审计档**：隔离策略变化、后端路由、连接器批准/撤销、逃逸或违规事件、Kill Switch 和凭据代理引用；用于安全调查和审计，采用 WORM/等价防篡改存储。
  - **合规保留档**：受法律、合同或调查保全约束的数据；仅授权合规主体可访问/释放，按法定或合同期限保留。
- 三档均遵守 `REQ-SEC-008` 的租户标识、区域驻留、访问控制和删除治理；记录按数据最小化原则保存，不写入秘密、完整令牌、无必要的源码或命令敏感参数。
- **检索 SLA**分别定义为可检索性目标（数据写入到可查询的最大延迟）和查询响应目标（指定范围/过滤下的响应时间）；按档位、时间范围、租户和查询类别评估。数值及分位口径需在 `REQ-OBS-007` 和存储成本评审中冻结，禁止本设计伪造指标。
- **WORM 与删除的边界**：WORM 不意味着超法规永久留存。保留期内按不可变策略写入；租户删除请求触发跨热/冷/WORM 索引、对象、派生副本、缓存和检索索引的删除/墓碑级联工作流。若法定保留或不可变锁阻止物理删除，立即隔离访问、记录阻止依据与到期条件，并依 `SEC-008` 合规删除审批处理；不得谎称即时物理擦除。
- 删除级联必须产生可审计删除证明，覆盖数据定位、执行/跳过状态、备份到期边界及保留例外；证明本身不得复现被删除的敏感内容。

### 5.5 跨平台策略与生产路径（Q5）

- **用户决策**：生产路径单一化、策略层抽象化、Windows 走虚拟化。
- **生产执行基线**：以 Linux 云端隔离执行为唯一生产路径，减少安全控制和审计口径分叉。Linux 路径后端仍可多样化，但均须通过统一能力契约和同一合规/安全基准。
- **策略层抽象**：统一声明工作区、文件、网络、进程、资源、身份、审计和生命周期策略；适配器负责映射到平台原语。策略意图一致不代表底层保障等价，每种后端/平台须报告能力差异并执行独立基准。
- **Windows**：开发者本地 Windows 环境不得直接承担生产 Agent 沙箱职责；需要本地执行时必须在受支持的虚拟化 Linux 环境中运行，生产同样路由到 Linux 执行面。具体虚拟化方案、Windows 客户端支持范围和运维责任待部署评审冻结。
- **macOS**：不作为生产执行路径；本地开发可用 OS 原语适配器，但该适配器仅为开发便利，不能作为生产隔离等级证明。

### 5.6 SLO 驱动自适应 WarmPool（Q6）

- **用户决策**：控制目标为沙箱分配延迟 p95 ≤ 200ms，通过反馈控制调节池。
- 指标从请求进入沙箱分配队列到获得满足策略等级、租户和区域要求的可执行实例；不把池内领取时间替代端到端分配时间。按隔离能力/后端、区域和租户服务等级分组统计，避免总体值掩盖冷门等级违约。
- 控制器以滚动窗口内 p95 偏差、到达率/并发、合格空闲实例数量、启动耗时分布、预热失败率和资源成本为输入，调整各池目标水位及预热并发。采用带迟滞、上下界和冷却时间的反馈控制，防止抖动、过度扩容和快速回收。
- 扩容优先增加当前 SLO 违约且预测有需求的合格池；缩容须在延迟稳定且保留安全容量后进行。实例仅在清除任务状态、凭据、卷、缓存和租户关联并通过基线复核后才可回池；无法证明清洁则销毁。
- WarmPool 只改善延迟，不是隔离边界；预热实例不可携带租户/任务数据或可复用秘密。不得为了达到 200ms 目标使用不匹配隔离等级的池。
- **待冻结**：滚动窗口、目标水位计算边界、迟滞/冷却时长、资源上限、成本预算和 SLO 统计排除规则需用目标部署负载基准确定。

## 6. 目标用户与典型场景

| 角色 | 场景 | 期望 |
|---|---|---|
| 开发者/任务发起人 | 提交仓库 Issue，要求 Agent 分析、编辑和测试 | 获得隔离符合任务要求的执行环境；不必自行维护执行主机 |
| 组织/团队管理员 | 配置允许的连接器与网络目的地 | 声明经审批后可追溯、可撤销，租户范围不会被其他团队继承 |
| 安全运营人员 | 查看隔离命中原因、出口阻断和异常 | 能以 Task、Worker、Sandbox、策略版本和 Trace 关联证据 |
| SRE/平台工程师 | 应对高并发及分配延迟 | WarmPool 根据 SLO 和成本自适应；不因容量不足降低隔离 |
| 合规人员 | 调查事件或响应租户删除请求 | 按用途档查询，留存例外透明，删除级联有证明 |

### 6.1 典型任务流程

1. 接收 Task 后，在读取仓库和创建执行环境前完成用户/租户授权及数据访问检查。
2. Planner/策略服务基于任务意图、数据分类、输入来源、拟用工具/连接器、写权限和外部副作用形成隔离需求；任务执行期间新发现的风险可提高需求。
3. 连接器拥有者提交目的地和能力声明；获批后产生版本。无所需连接器批准时，任务使用断网策略或阻塞等待批准，不自动猜测目的地。
4. 沙箱路由器应用多维触发矩阵，得到最低隔离能力；按硬性约束、区域、租户和可用容量筛除后端，再在合格集合内评估成本及延迟。记录选型原因和版本。
5. 从满足等级的池分配清洁实例或按后端能力创建实例；对镜像、运行身份、挂载、网络、资源、日志出口进行启动前验证。任何强制控制缺失均 fail-closed。
6. Setup 阶段只运行经审批的准备任务。网络目的地必须来自批准连接器版本；凭据仅按 `SEC-005` 代理/调用授权提供，不向沙箱提供长期秘密。Setup 结束时撤销临时能力并确认策略切换。
7. Agent 阶段默认无直接出站；需要外部交互时通过连接器代理执行，代理按已固化的连接器版本、任务身份、资源和操作校验。文件、进程、资源和每个工具 Action 同样受策略约束。
8. 完成、取消、超时或安全告警时，撤销外部能力，停止/隔离实例，收集最小必要证据并执行清理。清洁验证失败则销毁，不复用。
9. 事件依用途进入诊断、安全审计或合规保留档，应用租户访问、留存和删除级联规则。

## 7. 输入、输出与概念状态

### 7.1 输入

- 共享身份：`organization_id`、`team_id`、`task_id`、`workflow_id`、`worker_id`、`action_id`、`trace_id`、用户/工作负载主体。
- 代码工作区基线与不可变 `source_revision`，任务分支及允许的读写路径。
- `REQ-SEC-001` 风险结果及其依据；数据级别和来源信任标记。
- Worker 能力、工具/连接器需求、拟执行操作和副作用等级。
- 已批准连接器声明版本及网络策略版本；不存在时明确为空/拒绝。
- 租户最小隔离策略、区域/驻留策略、资源预算、策略版本。
- 后端目录的能力、健康度、容量、区域、版本和经验证基准状态。

### 7.2 输出

- 沙箱实例引用、所选后端及能力级别、策略版本和路由理由。
- 生效的文件系统/网络/进程/资源/身份/审计边界摘要。
- 生命周期状态和启动前策略验证结果。
- 与 Task/Worker/Action 关联的 Artifact、Evidence 和审计事件引用。
- 结构化拒绝/阻塞原因：无合格后端、连接器未批准、成本闸门、区域不匹配、策略无效、配置漂移或清理未验证。

沙箱返回给 Worker 的操作结果不得包含平台秘密或其他租户信息；具体错误应在安全与可诊断性之间最小披露。

### 7.3 状态与一致性

概念生命周期：请求中、路由评估、创建/预热、基线验证、准备阶段、Agent 执行、暂停/审批等待、清理、终止、失败隔离。具体运行时状态映射以 `REQ-RT-002` 为准；沙箱状态是执行资源投影，不另立 Task/Worker 的事实源。

生命周期变化以 `REQ-RT-003` 事件追加并由投影呈现；路由、策略版本、镜像摘要和连接器版本不可被原地覆盖。重试/恢复须经 `REQ-RT-005/007` 检查点与幂等边界校验。审批等待时按风险和凭据 TTL 撤销或冻结外部能力；恢复时重新验证授权、连接器版本、沙箱基线和隔离要求。

## 8. 后端路由与隔离要求

### 8.1 能力等级表达

不把某个产品名称等同于固定安全等级。后端适配器声明并经测试证据证明能力，至少包含：

- 执行边界：进程、容器、用户态内核、硬件虚拟化/独立内核等实际模型；
- 宿主共享程度、隔离租户粒度、宿主访问面和已知限制；
- 文件访问、符号链接/路径遍历语义、只读根文件系统、卷生命周期；
- 出站网络强制点、DNS/IP 校验能力、私网/元数据阻断、代理和 TLS 检查边界；
- 用户/能力、系统调用、进程数和资源配额限制；
- 租户与区域绑定、镜像来源验证、补丁状态；
- 启动/恢复分位延迟、容量、失败率、资源单价和可观测字段；
- 创建、暂停、快照、恢复、销毁、清洁验证能力。

能力声明必须指向适配器版本、运行时版本和可复现实测证据。能力未知、过期、未验证或健康状态不可确认，视为不满足该项约束。

### 8.2 路由顺序

1. 验证任务主体、租户、仓库、区域和策略版本；授权失败不创建沙箱。
2. 收集多维触发矩阵输入并形成“最低隔离要求 + 必须能力 + 不允许能力”的决策记录。
3. 若安全触发要求 Level 3，则把 Level 3 能力写为不可降级约束；用户或预算输入不得覆盖。
4. 从后端目录仅筛选满足全部硬约束、目标区域和当前可用性的后端。
5. 对合格候选执行成本闸门与延迟/SLO选择；无法满足时排队、拒绝或请求预算例外审批，不放宽隔离条件。
6. 创建/分配后核验实际运行配置与已批准能力。漂移或启动后验证失败时停止执行并隔离实例。
7. 将选型、淘汰原因、风险维度、成本结果、容量状态和策略/目录版本作为审计证据记录。

**单调规则**：路由结果是本次执行的最低边界；执行期间只能升级。已有任务更换后端时须确认新后端不低于旧边界并重新校验数据/连接器；不能满足则暂停并保留证据，不得降级迁移。

### 8.3 MVP 能力基线

- 云端生产执行只允许 Linux 执行路径；生产后端至少提供经安全评审的隔离运行时、非特权身份、最小系统能力、只读系统根、独立任务工作区、默认拒绝网络、硬资源上限、租户/区域约束和完整终止/清理能力。
- 仅有普通容器隔离的后端是否满足特定任务等级，必须由 SEC-001 威胁模型、宿主加固、运行时配置检查、逃逸测试及部署威胁假设共同批准；不得仅因叫 Docker 而自动判为足够。
- Level 3 的具体后端可以是经评审的微虚拟化或其他满足能力合同的隔离技术；本需求不预判名称或性能。若部署环境没有合格后端，对触发 Level 3 的任务 fail-closed。
- 每任务隔离身份、独立临时工作区、宿主敏感路径及容器/虚拟化管理 socket 不可暴露给 Agent。工作区外文件访问默认拒绝；显式只读挂载也必须基于最小化清单审批。

## 9. 文件、网络、凭据与两阶段执行

### 9.1 文件与进程边界

- 工作区按仓库和任务隔离；仅授权任务目录可写，系统镜像只读；禁止访问宿主 home、SSH、云凭据、容器运行时 socket、其他任务卷及其他租户数据。
- 路径校验按规范化后的最终路径执行，阻止路径遍历、符号链接越界、硬链接/挂载绕行和大小写/Unicode 规范差异造成的策略绕过。后端语义不支持完整强制时不得宣称等价能力。
- 进程采用非特权身份、最小能力、禁止提权；限制危险系统调用、子进程、打开文件、文件大小、CPU、内存、磁盘、I/O 和持续时间。具体上限由 Worker 基准及租户预算确定并由运行时硬性执行。
- 文件修改和命令调用均须绑定授权 Action；模型输出不直接成为执行授权。写操作与 PR/Git 副作用仍遵守 Policy Gateway、幂等及人工审查规则。

### 9.2 连接器和网络出口

- 平台不提供默认公共域名清单。任何公网或内部目的地必须由具体连接器声明、责任人审批并形成带期限的策略版本。
- Setup 与 Agent 阶段都遵守“声明—批准—下发”链路；Setup 不是绕过网络审批的特权阶段。仅阶段所需连接器可用，批准范围必须绑定任务、租户、执行阶段、后端和策略版本。
- Agent 默认不具有直接网络接口或直连出站能力；需联网时统一经过策略强制出口。代理不可用、解析歧义、策略过期或校验失败时拒绝连接。
- 网络决策至少记录连接器/策略版本、目标标识、解析后的网络类别、端口/协议、Action/Task 关联、允许/拒绝结果和时间。凭据及载荷不入日志。
- 禁止到云元数据、回环、链路本地、未批准私网和其他租户网络的访问；如企业连接器确需私网，应由租户显式配置与审批，不得被通用允许规则覆盖。

### 9.3 凭据边界

- 根凭据、长效刷新令牌及平台控制面凭据永不挂载或注入沙箱。
- 外部工具认证遵循 `REQ-SEC-005`。优先通过外置凭据/出口代理按工具调用绑定目标、操作、资源、Task 和审批引用；具体短期令牌不得超过 SEC-005 定义的范围与 TTL。
- 不把“Setup 阶段可用凭据”解释为“真实凭据可进入沙箱”。如第三方包管理器确需认证，凭据只可由外部代理代持/代注入到请求，不写入文件、环境、命令行、进程可读共享状态、日志或模型上下文。
- Setup 完成、任务暂停/终止、策略撤销或 Kill Switch 触发时撤销相应能力。清理未确认前实例不可回池。

### 9.4 Setup 与 Agent 阶段

两阶段是生命周期策略阶段，不是不同安全等级：

1. **Setup**：执行审核过的环境准备步骤；网络只使用获批连接器及目的地；安装脚本/依赖视为不可信代码，仍在本任务沙箱内运行；有独立时间、资源和输出限制。
2. **切换门禁**：完成/超时后终止子进程、撤销 Setup 专属授权、清除临时状态、核验代理策略和工作区；切换失败时禁止进入 Agent 阶段。
3. **Agent**：默认无直接出站；所有已批准连接器请求经外部策略出口控制；工具调用接受前置授权和执行后证据记录。
4. **结束**：停止进程、撤销凭据、清理或按经批准的检查点策略加密封存工作区。快照不得带入短期凭据、其他租户数据或可跨任务复用的环境秘密。

## 10. 生命周期、HITL 与失败处理

### 10.1 生命周期约束

创建前检查：租户/用户授权、区域、风险矩阵、后端能力、镜像摘要/签名策略、资源预算、连接器版本、审计可写性。运行前检查：实际隔离配置与批准决策一致、文件/网络/进程/资源控制生效。终止后检查：进程已停止、凭据已撤销、挂载/临时卷已清理、审计证据已持久化。任何无法验证的安全条件采取拒绝或隔离处理。

沙箱生命周期作为 Sandbox Resource 事件关联运行时事件，不复制 Task 状态机。强制终止请求应可与 `REQ-SEC-009` Kill Switch 协作；紧急停止时先阻断新 Action/出站并撤销能力，再停止执行资源和保全最小调查证据。

### 10.2 人类在环

- 连接器声明的初次批准、敏感目的地/私网访问、触发级别或风险例外、超出成本闸门预算、保留期/删除例外必须由授权角色批准。
- 运行中检测到新的 L3/L4 数据、低可信输入导致新外联需求、租户边界异常、隔离能力缺失或逃逸迹象时，系统先阻断/暂停再请求人工处置。
- 用户不得在单个任务界面将租户最低隔离要求调低；审批不能授权绕过平台强制禁止项。
- 控制台展示最少但充分的信息：要求的隔离能力、命中矩阵项、后端及版本、连接器/审批版本、预算影响、失败原因和审计引用。

### 10.3 故障与降级

| 故障 | 必需行为 |
|---|---|
| 无后端满足隔离要求/Level 3 无容量 | 排队、升级至合格后端或拒绝；绝不降级；给出原因并告警 |
| 连接器声明缺失/未批准/过期 | 网络请求拒绝；可暂停等待审批；不使用平台默认域名替代 |
| 策略、路由目录或租户区域不可用 | Fail-closed，不分配新实例、不允许新出站 |
| 启动基线与批准策略不一致 | 阻止 Worker 执行，隔离或销毁实例，生成安全事件 |
| 网络代理/凭据代理故障 | 拒绝相关外部调用；不让沙箱直连或使用缓存凭据绕过 |
| 资源超限 | 限制或终止对应任务；记录实测值与上限；不影响其他租户 |
| 沙箱逃逸/宿主访问信号 | 立即阻断出口、吊销凭据、停止任务并触发 Kill Switch；现场证据按最小必要保全 |
| WarmPool 清理/租户重置未验证 | 销毁实例，不返回可复用池 |
| 审计不可写 | 安全关键操作阻塞；是否允许纯只读诊断运行由策略另行确定，默认不执行写入或外联 |
| 任务暂停/恢复 | 暂停期间按 TTL 撤销凭据；恢复时重新评估路由、审批、镜像和策略版本 |

重试、恢复、检查点保留和补偿的详细语义由 `REQ-REL-*` 冻结；本需求不授权对未知副作用盲目重放。

## 11. 审计、数据治理与可观测性

### 11.1 必须可关联的证据

- Task/Workflow/Worker/Action/Trace、组织/团队、仓库 revision；
- 后端、适配器、运行时、镜像摘要、隔离能力声明及验证版本；
- 风险矩阵结果、命中原因、策略及连接器版本、路由候选及拒绝原因；
- 生命周期时间点、阶段转换、清洁检查结果、终止原因；
- 网络允许/拒绝元数据、资源上限/实耗、策略漂移和安全事件；
- 审批主体、范围、理由引用、有效期及撤销事件。

不得记录访问令牌、私钥、Cookie、连接器秘密、完整源码或默认完整命令参数。需要调查的命令/内容证据须经数据分类和脱敏策略单独批准。

### 11.2 指标

- 沙箱分配延迟 p50/p95/p99（目标：p95 ≤ 200ms，按能力池/区域/租户服务等级分组）；
- 冷启动、池命中率、池等待时间、池容量、预热成功率、创建失败率；
- 每后端安全要求满足率、配置漂移、隔离验证失败、逃逸/违规事件；
- 连接器审批版本分布、网络拒绝/允许数、代理不可用、目的地解析异常；
- CPU/内存/磁盘/运行时资源、每任务后端成本、超限和任务中止；
- 审计事件写入延迟、按用途档数据可检索延迟、查询响应分位、租户删除级联进度/失败数；
- 清理完整率、凭据撤销结果、异常回池阻断数。

指标标签须遵循 `REQ-OBS-003/004` 的低基数与脱敏要求；Trace 和审计留存分别遵循 `REQ-RT-006/008`、`REQ-OBS-007`。

### 11.3 人工评估

通过隔离矩阵用例、安全逃逸测试、连接器策略变更测试、故障注入、性能负载测试、成本核算及租户删除演练进行验证。成功任务率/模型质量不得抵消隔离安全门禁失败。

## 12. 性能、成本与延迟

- **已确认目标**：沙箱分配延迟 p95 ≤ 200ms。按满足相同隔离需求的可服务分组统计；同时报告请求端到端延迟和 WarmPool 命中情况，不能通过排除冷启动请求粉饰 SLO。
- WarmPool 控制器通过预热实例消化启动延迟，但资源成本、池空闲时长和预热开销须同步报告。控制器无法预测需求或成本达到硬上限时，可产生排队/拒绝，不能选用较弱隔离实例。
- 各后端冷启动、恢复、并发密度、系统调用/文件 I/O 开销和网络代理额外延迟需使用目标语言、典型构建/测试任务及安全对抗 workload 进行基准；不得把厂商或二手博客中的数字直接用作本系统 SLA。
- 单任务 CPU/内存/磁盘/运行时限、WarmPool 成本上限、预热资源预算和连接器代理开销为部署级待定参数。超成本时的行为遵循成本闸门，不关闭策略或延长凭据权限。
- P95 持续违约应触发控制器扩容/告警及容量复核；持续资源浪费应收缩非必要池，但满足安全预留容量和迟滞要求。

## 13. 可验证验收标准

以下标准验证设计落地后的实现，不代表本文档完成时已经通过。

| 编号 | 可验证标准 | 验证证据 |
|---|---|---|
| SEC-004-AC-01 | 所有生产沙箱由后端抽象创建；每个后端声明可核验能力、限制、版本和基准证据；未知能力视为不满足 | 后端契约审查、能力与运行配置一致性测试 |
| SEC-004-AC-02 | 路由使用独立多维输入；任一已配置 Level 3 触发项命中均选用达到 Level 3 的后端或阻塞 | 矩阵覆盖测试，对每个维度逐项与组合测试 |
| SEC-004-AC-03 | 任何成本闸门、容量、故障或用户请求都不能令运行要求低于已计算最低隔离能力；任务运行中只允许升级 | 属性测试/故障注入/审计记录检查 |
| SEC-004-AC-04 | Windows 本地 Agent 执行不进入生产执行路径；生产任务执行于 Linux 执行面；Windows 本地执行只能经批准虚拟化 Linux 环境 | 部署拓扑审查和路由集成测试 |
| SEC-004-AC-05 | 平台无通用预设网络白名单；未声明、未审批、过期或撤销的目的地全部被拒绝 | 空白配置测试、声明/审批/撤销生命周期测试 |
| SEC-004-AC-06 | 出口校验覆盖解析后私网、回环、链路本地、元数据地址、IPv4/IPv6 表示及 DNS 重绑定/重定向用例 | 网络对抗测试及代理证据 |
| SEC-004-AC-07 | Setup 与 Agent 阶段均执行连接器审批；Setup 完成后专属能力撤销；无长期凭据进入沙箱 | 流程测试、凭据扫描和受控进程/文件检查 |
| SEC-004-AC-08 | Agent 默认不能直连外网；代理不可用或策略不可确认时 fail-closed | 网络隔离测试、故障注入 |
| SEC-004-AC-09 | 任务工作区、宿主敏感路径、其他任务/租户卷和运行时管理接口相互隔离；清洁未验证实例不回池 | 路径/符号链接/挂载逃逸测试及复用测试 |
| SEC-004-AC-10 | 资源硬上限在对应后端生效，超限无法影响其他租户，并产生可关联审计证据 | 压力和多租户噪声邻居测试 |
| SEC-004-AC-11 | 事件按诊断、安全审计、合规保留三档路由；安全档具防篡改证据；租户删除级联覆盖所有副本或记录合法保留阻塞 | 留存/完整性/删除演练和删除证明审查 |
| SEC-004-AC-12 | 每档可检索性 SLA 有已批准数值、测量定义、实际观测及违约告警 | `REQ-OBS-007` 对齐后的可检索性基准报告 |
| SEC-004-AC-13 | WarmPool 控制以分组分配 p95 ≤ 200ms 为目标，反馈调节具迟滞、边界和冷却控制；成本与安全能力同时可观察 | 到达率阶跃/峰谷压测、SLO 与成本报告 |
| SEC-004-AC-14 | WarmPool 实例回收时清理任务状态、凭据、卷、缓存及租户关联；验证失败则销毁 | 污染复用和清理失败注入测试 |
| SEC-004-AC-15 | 逃逸/越权信号触发出口阻断、凭据撤销、任务停止及 `SEC-009` 事故流程；全链路证据可关联 | 端到端演练、撤销与停止时间记录 |
| SEC-004-AC-16 | 沙箱生命周期、策略版本、后端/镜像、连接器、租户、Task/Worker/Action/Trace 可审计关联，日志不含秘密 | 查询审查、脱敏测试及审计样本抽查 |
| SEC-004-AC-17 | 目标生产后端完成针对预期对手、逃逸路径和代表性负载的独立基准；严重安全失败阻止其进入路由目录 | 安全评审签署、版本化基准及发布记录 |

### 13.1 最低安全验证场景

- 路径遍历、符号链接/硬链接、挂载和大小写/Unicode 路径绕过；
- 宿主敏感路径、其他沙箱/租户数据、容器/虚拟化管理接口访问；
- 元数据 IP、回环、私网、链路本地、DNS 重绑定、CNAME/重定向、IPv6 表示及 DNS 隧道；
- 危险系统调用、提权、跨进程访问、fork/资源耗尽、持久化尝试；
- 恶意依赖安装脚本在 Setup 阶段尝试访问未批准服务或读取秘密；
- 连接器审批撤销/过期、策略版本漂移、代理不可用和身份伪造；
- 任务暂停、崩溃恢复、快照迁移、池复用中的凭据/租户状态残留；
- 审计服务不可用、WORM 保留期冲突及租户删除级联失败；
- Level 3 命中、成本超限、合格池耗尽、后端失效时的禁止降级验证。

测试应在隔离的专用测试环境使用合成或脱敏数据；破坏性测试不得在共享生产环境运行。SEC-010 负责完整红队计划，本节为沙箱专项最低回归集合。

## 14. 依赖与概念接口

| 依赖/消费者 | 概念契约 |
|---|---|
| `REQ-RT-001/002/003/005/006/007/008` | 共享 Task/Worker/Action/Artifact/Evidence/Trace、生命周期事件、检查点、幂等、查询/留存坐标 |
| `REQ-SEC-001` | 威胁场景、风险事实及解释；不把单个 `risk_level` 当作路由全部输入 |
| `REQ-SEC-002/003` | 主体/资源/操作授权、策略决策、审批与策略版本；默认拒绝 |
| `REQ-SEC-005` | 凭据代理和撤销；沙箱不持有长期凭据 |
| `REQ-SEC-006` | 不可信来源及注入检测信号；新增风险可升级隔离，不可降低 |
| `REQ-SEC-007` | MCP/连接器身份、目的地/操作声明、审批版本和隔离要求 |
| `REQ-SEC-008` | `organization_id/team_id`、区域驻留、租户删除级联、留存例外 |
| `REQ-SEC-009` | 紧急阻断出口、吊销能力、停止/隔离实例及事故处置 |
| `REQ-HAR-001/003/005` | Harness 生命周期、工具执行边界和统一路由；所有执行请求关联 Sandbox Resource |
| `REQ-REL-004/005` | 检查点、恢复前重验和失败处置；不盲目复用实例 |
| `REQ-OBS-001/002/003/004/007` | Trace/Event/Evidence、指标、脱敏、高基数和审计留存完整性 |

概念数据流：策略/授权服务形成执行约束；沙箱路由服务选择满足约束的后端；后端执行适配器创建实例；连接器/出口代理按批准版本处理外联；事件与指标服务保存证据。执行平面不能修改控制平面的路由策略、连接器批准、身份或审计规则。

## 15. 版本与演进

### 15.1 MVP

- 单一 Linux 云端生产路径；隔离后端使用统一能力抽象，部署评审确定首个生产适配器。
- 先支持满足已批准安全基线的后端；Level 3 若无合格实现则阻塞相应任务，不以低级别替代。
- 连接器声明、人工/策略审批固化版本、任务绑定运行时下发；无平台预置通用网络白名单。
- 多维触发矩阵、单调升级、禁止运行中降级和成本闸门；具体阈值待基准和评审冻结。
- 三档审计用途、WORM 安全档、检索可检索性 SLA 和租户删除级联；时长与分位数待合规/运营评审冻结。
- SLO 驱动 WarmPool，分配 p95 ≤ 200ms 作为控制目标；反馈参数和成本上限需实测定标。

### 15.2 后续演进

- 增加经威胁评审和基准测试的新后端/隔离强度，不改变抽象策略消费者。
- 支持更多区域、客户专用执行池、专属宿主或硬件隔离；服从 `SEC-008` 驻留及租户规则。
- 对连接器提供声明模板和变更影响分析，但模板只能建议，不能自动批准。
- 以实际到达率、延迟和成本数据改进 WarmPool 预测/控制器；任何学习型优化只能影响合格池容量选择，不能降低隔离要求。
- 评测数据不足时，算法仍保持保守规则路由；自动策略优化须有回滚、审计和独立门禁。

### 15.3 复评触发条件

新增执行平台/后端、OS/内核/虚拟化重大升级、租户模型或数据等级变化、引入私网连接器、严重逃逸/数据外泄事件、策略或能力验证失败、WarmPool 违约/超支、法规/合同/云供应商边界变化时复评；至少按季度复核后端能力与连接器批准状态。

## 16. 待确认及评审问题

Q1-Q6 的方向已确认；以下是将方向变成可实施基线前仍需评审冻结的参数/责任边界，不阻止本版本设计完成，但阻止宣称实现基线已冻结：

1. Level 3 触发矩阵各维度阈值、数据分类与 SEC-001 风险等级之间的映射责任人。
2. Level 3 合格后端清单、目标部署区域、运行时/宿主威胁假设和能力复验周期。
3. 成本闸门预算口径、审批角色、预算例外有效期及容量不足等待上限。
4. 连接器声明的批准主体、有效期默认值、私网目的地审批和紧急撤销时限。
5. 三类审计记录的具体保留期限、WORM 锁定策略、合法保留解除及 SEC-008 删除级联在备份中的边界。
6. 各档数据写入可检索延迟和查询响应 SLA 的分位数、查询范围、采样/测量窗口及违约处理。
7. WarmPool 控制窗口、预热并发上下限、迟滞/冷却时长、最低容量及单位成本预算。
8. Windows 虚拟化 Linux 的本地支持范围、客户端运维责任及生产构建/调试差异。
9. `SEC-009` Kill Switch 的端到端停止 SLO 与现场证据保全最小集合。
