## 2. 实施前证据与问题

| 位置 | 已观察到的行为 | 对本任务的影响 |
|---|---|---|
| [MCPProtocolHandler](../../src/security/mcp_connector_governance/protocol/mcp_handler.py) 的 tools/list | 过滤黑名单及组织裁剪，但不检查提供方生命周期；无提供方时可原样返回工具 | 暂停、撤销、过期或孤立条目可能继续暴露 |

| [ToolExecutor v2](../../src/security/mcp_connector_governance/execution/tool_executor_v2.py) | 生命周期检查后异步准备凭据，再扣配额和传输 | 凭据等待期间停用，需在交给传输前复核状态 |

## 3. 官方对标分析

核验日期为 2026-10-28。只引用已打开的官方页面；公开行为和本项目决策分列。

| 产品/规范 | 官方公开做法 | 优点 | 本项目借鉴与边界 |
|---|---|---|---|
| [Cursor MCP](https://cursor.com/docs/mcp#can-i-temporarily-disable-an-mcp-server) | 在 Customize 中开关服务器，停用后不加载、不出现在聊天中；本地与 Cloud Agents 登录分别管理 | 开关状态与模型可见能力一致，凭据作用域清晰 | 停用提供方不参与工具发现；本地失效不能写成云端/远端已吊销 |
| [Claude Code MCP](https://code.claude.com/docs/en/mcp#disable-a-server-without-removing-it) | 可保留配置而停止连接；Disable/Clear authentication 会清除该服务器发现缓存；删除远程服务器还会删除本地保存的 OAuth 信息 | 配置保留、发现失效、认证清理有明确语义 | 每次发现查权威状态；后续凭据切片独立验证，不把隐藏工具当作凭据吊销 |
| [MCP Tools 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/server/tools#list-changed-notification) | 定义 tools/list；声明 listChanged 的服务应在清单变化时发通知 | 客户端可更新发现结果 | 本切片保留仓库已有请求/响应形状，每次请求重算；没有实现通知能力前不承诺主动推送 |

本项目结论：生命周期过滤必须同时存在于发现和调用入口；发现结果只是能力提示，执行时仍须检查。此为结合现有需求作出的设计选择，不推断竞品内部授权或撤销算法。对标不构成本轮 MCP 协议升级，2025-11-25 仅为已有设计所引用的规范版本。

## 4. 拟实施方案

### 4.1 范围与可观察行为

1. 只有注册表中存在、状态为 ACTIVE/RESTRICTED、且通过既有黑名单和组织可见性限制的提供方参与发现。RESTRICTED 继续应用现有能力裁剪，不额外授权。
2. PAUSED、REVOKED、EXPIRED、HEALTH_ANOMALY、PENDING_REVIEW，以及草稿/验证/审批等非可调用状态均不暴露工具。未知状态按拒绝处理。
3. 没有提供方、提供方记录丢失、所有提供方停用时，省略该工具。未装配连接器注册表时返回配置错误；查询异常返回统一错误，不能回退为全部工具。
4. 多提供方共享工具时，仅合并可用提供方的裁剪规则；停用方不能贡献描述、Schema 或更宽参数取值。工具定义取提供方自己登记的版本，不从全局版本列表猜测。
5. 保留 tools/list 当前按工具名聚合的返回形状。可用提供方的同名定义不一致时，暂时隐藏该歧义条目并记录原因；不任意选择一个定义。tools/call 继续按已有 connector_id:tool_name 精确定位，并取该提供方的定义。统一对外命名及完整 Schema 审批属于后续切片。
6. tools/call 对当前非可调用连接器在执行器之前拒绝；执行器已有门禁保留。v2 凭据准备结束后、扣配额及交给传输前再次检查状态，覆盖本进程内等待期间的停用。
7. 暂停后再次 tools/list 立即反映状态；合法恢复后重新计算，仍受原签名、黑名单、组织策略和执行检查约束。生命周期迁移本身沿用现有管理器及事件记录。

生效边界为本进程内、尚未交给传输执行的调用。已发送的外部副作用无法由隐藏工具撤回；跨进程传播、连接器版本替换、暂停后快速恢复的代次识别、缓存凭据撤销仍是后续生产闭环的验收项。

### 4.2 API 契约（2026-10-28 已确认，先于代码）

本任务使用现有内部 Python API 和 JSON-RPC，不新增 HTTP 管理端点。参数、结果与错误包络沿用[API 说明](../api/sec-007-mcp-connector-governance-api.md)。

| 接口 | 拟议契约 |
|---|---|
| ToolRegistry.register_tool(tool, connector_id) | 签名不变；额外保存该提供方对应的当前定义，保留全局历史查询兼容性 |
| ToolRegistry.get_tool_for_connector(connector_id, tool_name) -> ToolSchema 或 None | 新增内部读取接口；未知提供方、未登记工具均为 None；不得返回其他提供方版本 |
| ToolRegistry.unregister_connector(connector_id) | 同步移除该提供方定义关联，保留仍被其他提供方引用的版本 |
| MCPProtocolHandler.handle_request(request_json, org_id, user_id) | 签名不变；org_id/user_id 仍由可信上游传入，不能由请求 params 覆盖 |
| tools/list | 不新增必填参数；仍返回 result.tools，字段 name/description/inputSchema 不变；过滤后为空时返回 tools: []；无注册表或查询异常返回 -32603 |
| tools/call | 保留现有 connector_id:tool_name 语法；不可用/不存在目标均返回 -32050 和通用 Tool unavailable，不泄露其他提供方或凭据；不得调用传输、不得扣配额 |
| ToolExecutor.execute_tool(...) | 签名不变；v2 等待后状态检查拒绝时 success=false、metadata.blocked_by=lifecycle，沿用既有审计入口；其他失败格式不变 |

兼容性变化须随本方案批准：过去无连接器注册表也可能列出工具，现在返回配置错误；不可用工具将从列表消失；同名歧义条目不再任意暴露；调用非活动连接器的协议错误统一为 -32050。现有调用方及测试夹具随实现同步。

### 4.3 文件范围与顺序

1. 先更新现有 API 文档，把批准后的契约从草案转为本次实施要求；列出兼容性变化。

4. 联调注册 → 发现 → 暂停 → 列表移除 → 缓存名称直接调用拒绝 → 合法恢复的路径，使用本地测试传输观察实际调用次数。
